# 일반 회사 파일럿 UAT 실행서

## 목적과 범위

실제 production 전환 전에 승인된 staging에서 가상 또는 비식별 자산으로 직원·담당자·관리자의 업무 적합성을 확인한다. 실제 비밀번호·토큰·개인정보는 증거 파일에 기록하지 않는다.

## 사전 조건

- HTTPS staging, 회사 OIDC, 외부 저장소·악성코드 검사기 readiness 통과
- 검증된 release tag와 migration 14개, 필수 테이블 32개
- 최신 백업 checksum과 격리 복구훈련, 운영 상태·비기능 게이트 통과
- 직원·담당자·관리자 계정과 서로 다른 부서 표본 준비

## 역할별 시나리오

### 직원

1. SSO·MFA 로그인, 만료 후 401, 로그아웃을 확인한다.
2. 허용 부서 자산만 조회하고 다른 부서 상세가 403인지 확인한다.
3. 배정·반납·구매 요청을 작성하고 반납 사진을 제출한다.
4. 세션이 다른 탭에서 갱신된 뒤 기존 입력이 유지되고 재제출 안내가 표시되는지 확인한다.

### 비품 담당자·부서장

1. 하위 부서 범위와 타 부서 비노출을 확인한다.
2. 순차 승인·반려·자기승인 차단을 확인한다.
3. 입고·검수·배정·수리·실사·폐기 흐름을 확인한다.
4. 동일 Idempotency-Key 재전송으로 업무 행이 한 번만 생성되는지 확인한다.

### 관리자

1. 사용자 초대·취소·권한·부서 범위와 재인증을 확인한다.
2. 기준정보·승인 정책·감사 검색·CSV 다운로드를 확인한다.
3. cross-site 403, 악성파일·unknown·timeout 차단, readiness 503을 확인한다.
4. 운영 상태·백업복구·비기능·rollback 증거를 검토한다.

## 결함 기준

- Critical: 인증 우회, 데이터 범위 노출, 원장 손상, 복구 불가
- High: 핵심 승인·대여·반납·구매·감사 흐름 실패
- Medium/Low: 우회 방법이 있는 사용성·표시 문제

Critical·High 미해결 건이 하나라도 있으면 NO-GO다. 결함에는 ID·역할·재현·기대·실제·담당자·수정 버전·재검증 증거를 기록한다.

## 최종 승인

역할별 증거를 `cutover-evidence.json`의 `pilot.roleResults`에 연결하고 12개 게이트를 PASS로 채운다. 업무·보안·운영 책임자가 서명한 뒤 `npm run operations:cutover-gate -- <파일>`을 실행한다. 템플릿이나 빈 서명은 실제 배포를 승인하지 않는다.
