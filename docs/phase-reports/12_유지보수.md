# Phase 12 보고서 — 유지보수

## 완료 정의

운영자가 상태를 반복 점검하고 PostgreSQL 백업을 복구 가능한 증거와 함께 검증하며, 장애·보안·변경 작업의 시작과 종료 기준을 문서와 실행 명령으로 재현할 수 있는 상태를 완료 기준으로 삼았다.

## 구현 결과

- `maintenance:check`: frontend/API health와 DB 용량·핵심 건수·저재고·연체·만료 세션·필수 테이블 읽기 전용 점검
- `db:backup`: PostgreSQL custom-format 백업, 크기 및 SHA-256 기록
- `db:restore-drill`: 고유 임시 DB 복원, 원본·복구본 건수 비교, 임시 DB 안전 제거
- `docs/maintenance.md`: 주기, RPO/RTO 훈련 기준, 장애 등급, 백업 보안과 변경 흐름 정의
- `develop docs/13_유지보수_런북.md`: 일상·월간 체크리스트와 실행 명령 제공
- 백업 디렉터리를 Git에서 제외하여 운영 데이터의 저장소 유입 방지

## 데이터·개발·배포 흐름 반영

방향 준비 → 설계 → 구현·검증 → 출시 → 운영 흐름을 완결했다. 운영 변경도 Issue → branch → 구현 → 단위 테스트 → 문서 및 commit → PR을 따른다. 장애 시 상태 확인 → 스모크 → 로그 → 성공 또는 검증 태그 롤백·백업 복구 순서를 사용한다.

## 종료 판정
