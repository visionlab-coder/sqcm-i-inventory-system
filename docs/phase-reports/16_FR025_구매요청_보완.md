# Phase 16 FR-025 구매 요청 보완 보고서

상태: 부분 완료 — 자동 브라우저 인수 대기

## 목표

직원이 품목·수량·금액·비용센터·필요일·사유를 누락 없이 입력하고 서버가 검증한 구매 요청만 저장하게 한다.

## 변경 산출물

- Issue: GitHub #3
- 메타프롬프트: `agent docs/09_FR025_구매요청_메타프롬프트.md` (1,849자)
- 설계: `develop docs/16_FR025_구매요청_설계체크리스트.md`
- Service: 구매 payload 정규화·필드 오류·매개변수 JSONB 저장
- UI: 요청함 구매 요청 폼과 구매정보 요약
- 화면: 기존 요청함 페이지 HTML mock 보완, 제작 메타데이터 없음
- 테스트: 구매 정상·누락·범위·날짜·조직 권한·감사·정리

## 데이터 흐름

Browser → Nginx → `/api/enterprise/requests` → 세션·CSRF → Router → `createRequest` → `normalizePurchasePayload` → PostgreSQL 요청·감사 트랜잭션 → JSON → 요청함 재조회.

## 개선 루프

1. 대상 통합 테스트 파일에서 기존 기본 테스트 비밀번호 문자열을 발견했다.
2. 새 비밀번호 문자열을 추가하지 않고 기존 `getConfig()` 환경 주입 경계를 재사용하도록 정리했다.
3. 통합 6/6을 재실행해 동작을 확인했다.
4. 자동 브라우저 연결은 같은 커널 자산 경로 오류가 두 번 반복되어 별도 브라우저 도구로 우회하지 않고 중단했다.

## 미완료와 종료 조건

자동 브라우저에서 직원 로그인 → 요청함 → 6개 필드 표시 → 정상 초안 생성 메시지 → 구매 요약 표시를 확인해야 Phase를 완료한다. 확인 전에는 FR-025를 완료 23건 수치에 포함하지 않고 Issue #3을 열어 둔다.

다음 기능 후보는 FR-026/027 발주·부분 입고·검수 후 사용가능 자산 생성과 검수 전 배정 차단이다.
