# Phase 5 변경 보고서 — Docker 3계층 분리

## 목표

기존 애플리케이션·DB 2서비스 구성을 프론트엔드, 백엔드, 데이터베이스의 독립된 3서비스로 변경한다.

## 변경 결과

| 계층 | 구현 | 경계 |
|---|---|---|
| 프론트엔드 | Nginx + 정적 SPA | UI 제공, `/api` 프록시만 담당 |
| 백엔드 | Node.js + Express JSON API | 인증·권한·검증·업무 규칙 담당 |
| 데이터베이스 | PostgreSQL 16 | 영속 데이터와 세션 저장 담당 |

기존 EJS 경로는 호환성을 위해 유지하되 신규 Docker 진입점은 독립 SPA와 JSON API를 사용한다. 브라우저는 DB 또는 백엔드 내부 포트에 직접 접근하지 않는다.

## 성공 기준과 결과

- [x] Compose 서비스 수가 정확히 3개
- [x] 각 서비스 독립 이미지 또는 공식 DB 이미지 사용
- [x] database → backend → frontend 순차 health 의존성
- [x] 세 컨테이너 모두 healthy
- [x] 프론트 health와 `/api/health` 프록시 통과
- [x] API 로그인·세션·대시보드 통과
- [x] PostgreSQL 등록·대여·반납 통과
- [x] 실제 브라우저 로그인·대시보드 통과

## 실패·개선 기록

Nginx 컨테이너의 최초 healthcheck가 `localhost` 연결에 실패했다. 서비스 기능은 정상이었으며, 대상을 `127.0.0.1/health`로 고정한 뒤 재빌드하여 정상 상태를 확인했다.
