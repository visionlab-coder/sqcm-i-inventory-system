# Phase 17 FR-026/027 부분 입고·검수 보고서

상태: 완료 — 브라우저 런타임 외부 장애는 기존 FR-025 인수 항목으로 분리

## 목표와 완료 정의

승인된 구매요청을 한 번 발주하고 요청수량 이내에서 부분 입고하며, PASS 검수 시에만 입고수량만큼 개별 자산을 만든다. 검수 전 배정, 초과 입고, 중복 검수를 차단한다.

- 테스트: 단위 정규화 2건, 실제 HTTP·PostgreSQL 업무 왕복 1건 추가

## 데이터 흐름과 원자성

`승인 요청 → 발주 잠금 → 부분 입고 잠금·누적 계산 → 검수 잠금 → PASS 자산·이력·검수연결·감사·outbox → COMMIT`

자산은 PASS 트랜잭션 전에는 생성되지 않는다. FAIL/CONDITIONAL은 입고만 `REJECTED`로 바꾸며 자산을 만들지 않는다. 요청당 발주, 입고당 검수, 자산당 검수 연결은 유일 제약으로 이중 처리되지 않는다.

## 개선 루프

첫 통합 실행에서 테스트 정리 순서가 `inspections.asset_id` FK보다 먼저 자산을 삭제했고 migration 기대 목록이 3개로 고정되어 2건 실패했다. FK 순서대로 검수 후 자산을 삭제하도록 수정하고 기대 목록을 4개로 갱신했다. 남은 표식 요청 1건의 ID·하위 건수를 먼저 조회한 뒤 해당 계층만 트랜잭션 정리하고 7/7을 재검증했다.

## 잔여 위험

Codex 브라우저 런타임이 `failed to write kernel assets` 경로 오류로 시작되지 않았다. 앱의 HTTP·DB·Docker 검증과 분리했으며, FR-025 실제 브라우저 인수와 함께 재시도한다.
