# 유지보수 보완 보고서 — 품질 게이트·보안·관측

## 목표

전역지침과 실제 산출물을 1:1로 재검사해, 통합 테스트가 실행되지 않아도 성공하는 허위 양성을 최우선으로 제거하고 운영 보안·DB 변경·감사 추적의 문서/구현 불일치를 해소한다.

## 보완 결과

- `npm test`를 skip 없는 단위 검사로 명확히 분리하고, `test:integration`은 필수 환경변수 누락 시 exit 2로 실패한다. 구문 검사는 소스·프런트·스크립트·테스트의 JS/MJS 전체를 자동 탐색한다.
- GitHub Actions가 push/PR마다 단위 검사를 실행하고 별도 Job에서 frontend/backend/database를 기동해 통합 테스트를 필수 수행한다.
- 로그인에 IP+정규화 이메일 기준 fixed-window 제한과 429/Retry-After를 추가했다.
- 모든 API 응답에 `x-request-id`, 오류 본문에 code/message/fieldErrors/requestId를 제공한다.
- HTTP·오류·DB·서버 수명주기 로그를 비밀값 없는 JSON으로 남긴다.
- 감사 로그에 request ID와 IP를 저장하고 관리자 화면에서 조회한다.
- SQL 파일을 이름순으로 1회만 적용하고 SHA-256 변조를 탐지하는 `schema_migrations`를 추가했다.
- 운영 시작 시 32자 이상 세션 비밀과 secure cookie, 유효한 포트·레이트리밋 값을 강제한다.
- 배포 후 구버전 SPA가 남지 않도록 HTML은 no-store, CSS/JS는 버전 키로 캐시를 무효화한다.
