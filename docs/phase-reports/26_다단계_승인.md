# Phase 26 FR-020 다단계 승인 보고서

상태: 완료

## 구현 결과

- 조직·요청 유형·구매 금액 구간·우선순위별 정책과 1~10개 순차 단계를 PostgreSQL로 관리한다.
- 제출 시 정책 스냅샷을 요청별 승인 이력으로 생성하며 기본 1단계 정책은 기존 흐름을 보존한다.
- 현재 단계만 `FOR UPDATE`로 잠가 처리하고 MANAGER/ADMIN 역할, 부서 범위, 자기 승인 금지를 함께 검사한다.
- 중간 승인에서는 요청과 자산을 변경하지 않고 다음 단계만 연다. 최종 승인에서만 기존 `applyApprovedRequest`를 호출한다.
- 반려 시 현재 단계는 REJECTED, 나머지는 SKIPPED가 되며 요청·승인·업무·감사·Outbox는 한 트랜잭션이다.
- 관리자 UI에서 정책을 등록·조회하고 요청함에서 승인 진행률을 표시한다.

## 검증

| 항목 | 결과 |
|---|---|
| 구문·단위 | JavaScript 44개, 59/59 통과 |

| 2단계 | 1단계 후 SUBMITTED·자산 AVAILABLE 유지, 2단계 후 APPROVED·ASSIGNED |
| 역조건 | MANAGER의 ADMIN 단계 처리 403, 자기 승인 기존 방어 유지, 처리된 단계 재사용 불가 |
| 반려 | 1단계 REJECTED, 후속 단계 SKIPPED, 업무 미반영 |
| 감사 | 정책 생성·단계 승인·최종 승인/반려 이벤트 연결 |
| 정리 | 정책·요청·승인 이력·자산·세션 테스트 데이터 제거 |

## 미결정 운영 정책

실제 승인자 개인 지정, 대결 기간, 외부 전자결재·알림 규격은 저장소에서 임의 결정하지 않았다. 현재 산출물은 역할·부서·금액 기반 실행 가능한 정책 엔진이다.
