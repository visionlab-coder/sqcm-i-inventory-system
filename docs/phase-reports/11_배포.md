# Phase 11 보고서 — 배포

## 목표와 완료 정의

검토자가 GitHub commit을 받아 프런트엔드·백엔드·PostgreSQL 3계층을 안전하게 재현하고, 배포 전 실패를 차단하며, 배포 후 health와 핵심 경계를 확인할 수 있는 상태를 완료 기준으로 삼았다.

## 구현 결과

- `compose.yaml`: 로컬 개발 구성으로 명확히 분리하고 `FRONTEND_PORT`, `RELEASE_TAG`를 지원
- `compose.production.yaml`: 필수 비밀값, production 환경, secure cookie, no-new-privileges, 로그 순환 적용
- `.env.production.example`: 비밀값 없는 운영 환경 템플릿 제공
- `scripts/deploy-precheck.mjs`: 길이·예시값·계정 간 중복·포트·태그·secure cookie 검사
- `scripts/deploy.ps1`: 사전검사 → Compose 검사 → 빌드·기동 → health 대기 → 스모크 → 상태 확인 자동화
- `scripts/deploy-smoke.mjs`: 프런트/API health, 익명 401, 공식 반전 로고 자산 검사
- 운영 구성에서는 프런트 포트만 공개하고 backend와 database는 Docker 내부망에 유지
- 이미지에 `RELEASE_TAG`를 부여하여 직전 검증 태그로 롤백 가능

## 검증 결과

| 검증 | 결과 |
|---|---|
| 약한 값·누락 값 사전검사 | 의도한 실패 및 배포 중단 |
| 강한 임시값 사전검사 | 통과 |
| 운영 Compose 렌더링 | 통과 |
| `/health` | 200, JSON 계약 통과 |
| `/api/health` | 200, JSON 계약 통과 |
| 익명 `/api/items` | 401 |
| 공식 반전 로고 | 200, 이미지 형식 |
| 실행 중 Docker 3계층 | frontend/backend/database 모두 healthy |

첫 스모크 실행에서 프런트 health 본문과 로고 파일명의 기대값이 실제 계약과 다른 점을 발견했다. 실제 Nginx JSON 계약과 공식 반전 로고 경로로 검사기를 수정한 뒤 전 항목이 통과했다.

## 배포 흐름

방향 준비 → 검증 commit 선택 → 비밀값 사전검사 → 운영 Compose 렌더링 → 빌드·기동 → health → 스모크 → 로그 확인 → 성공 태그 또는 롤백 순서로 고정했다. Issue → branch → 구현 → 테스트 → 문서 → commit → push 흐름을 유지한다.

## 범위와 보류

로컬 Docker 운영 패키지와 릴리스 리허설은 완료했다. 외부 서버, 도메인, TLS 인증서, 비밀 저장소, 백업 저장 위치는 아직 지정되지 않았으므로 외부 공개 배포는 수행하지 않았다. 이는 배포 실패가 아니라 승인과 인프라 입력이 필요한 다음 실행 경계다.
