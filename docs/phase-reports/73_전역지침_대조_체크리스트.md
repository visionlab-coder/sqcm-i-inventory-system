## 3. 전역지침 파일 동기화 관찰

- 프로젝트 `AGENTS.md`와 `CLAUDE.md`는 동일한 프로젝트 정책을 담고 있다. SHA-256은 각각 `3E7C22...83935`와 `FE240E...41828`로 다르며, 차이는 Codex/Claude에서 반대 파일을 가리키는 우선순위 문장이다. 이 차이는 프로젝트 전용 파일의 정상적인 도구별 참조 차이로 보이며, 사용자 승인 없이 덮어쓰지 않았다.
- `Codex_1-6일차_통합전역지침_복사용.md`와 `Claude_1-6일차_통합전역지침_복사용.md`는 본문이 같고 제목·저장 대상 안내만 다르다. SHA-256이 다른 것은 이 두 줄 때문이다.
- 로컬 `00_1-7일차_통합전역지침.md`와 `06_프롬프트_에이전트_검증_전역지침.md`는 8단계 사고·12단계 프로세스·표준 prompt field를 보존한다. 현재 새 프로젝트 라우터는 이를 `bamsoft-web-process-11`과 `bamsoft-prompt-engineering` Skill로 위임한다.
- 누락으로 판정한 부분은 전역지침 파일을 임의로 수정하지 않고 이 보고서에 기록했다. 전역 정본의 실제 staging 원본과 양 플랫폼 미러를 바이트 일치시키는 작업은 별도 승인·전역 범위 작업이다.

## 4. 완성까지 남은 외부 게이트

1. AI PC 운영자가 독립 runtime·모델 checksum·bridge listener·health/ready·TLS·인증 증거 제공
2. 백엔드→bridge 계약 테스트와 조직 경계·fallback·감사 로그를 사무실 네트워크에서 실행
3. Secret Manager/OIDC/DNS/TLS/백업·PITR/경보 수신을 실제 대상에 연결하고 증거 수집
4. 관리자·현장 사용자 역할별 브라우저 반응형·접근성·UAT 서명
5. 승인된 리뷰어가 draft PR #10을 검토하고 merge/release 승인

위 항목 전에는 제품을 `Production GO`로 판정하지 않는다. 저장소 내부 READY는 현재 변경 commit·push·PR CI 확인이고, 외부 READY는 AI PC 운영자의 G1~G3 증거 제출이다.
