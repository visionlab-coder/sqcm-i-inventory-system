# 서원토건 비품관리시스템 유지보수 계획

## 운영 목표

- 비품 등록·대여·반납과 감사 이력의 가용성·무결성 유지
- 장애를 조기에 발견하고 검증된 이미지 또는 백업으로 복구
- 비밀정보와 개인정보가 로그·Git·공개 저장소에 남지 않도록 관리
- 모든 변경을 Issue → branch → 구현 → 단위/통합 테스트 → 문서 → commit → PR 순서로 추적

## 점검 주기

| 주기 | 점검 항목 | 증거 |
|---|---|---|
| 매일 | frontend/API/DB health, 5xx, 로그인 실패 급증, 백업 성공 | 상태 점검 출력, 로그, 백업 SHA-256 |
| 매주 | DB 용량, 저재고·연체, 만료 세션, 감사 로그 표본, 디스크 여유 | 주간 체크리스트 |
| 매월 | 격리 복구 훈련, 운영 의존성 audit, 계정·권한, 이미지 갱신 검토 | 복구 건수 비교, audit 결과 |
| 분기 | 장애 대응 훈련, 용량 추세, 보존기간 만료 자료, RPO/RTO 재검토 | 훈련 보고서와 개선 Issue |

## 기준

- 훈련 기준 RPO: 최근 정상 일일 백업 이내(최대 24시간)
- 훈련 기준 RTO: 장애 선언 후 4시간 이내
- health 실패 또는 전체 로그인 불가: P1
- 5분간 5xx 5% 이상, 핵심 기능 일부 불가: P2
- 저재고·연체·단일 사용자 문의: P3 업무 처리

실제 운영 SLA는 서버·백업 저장소·담당자 근무 체계가 확정될 때 승인된 값으로 대체한다.

## 장애 처리

감지 → 영향 범위 제한 → 증거 보존 → 최근 앱/DB/인프라 변경 분류 → 검증 이미지 롤백 또는 승인 백업 복구 → health·스모크 재검증 → 원인·영향·시각·조치·복구 기록 순서로 처리한다. 운영 데이터 삭제나 임의 SQL 복구는 금지한다.

## 백업 보안

백업에는 계정과 비품·감사 데이터가 포함되므로 암호화 저장소에 보관하고 최소 권한을 적용한다. Git에 추가하지 않으며 복구 훈련은 고유한 임시 DB에서만 수행한다. 기본 보존안은 일일 7개, 주간 4개, 월간 12개이며 법적·회사 정책 승인 후 확정한다.

## 확장 후보

실 OIDC·객체 저장소·악성코드 검사 공급자 연결, QR·바코드, 이메일·메신저 알림, 중앙 로그·메트릭과 자동 CI/CD를 승인된 후속 운영 작업으로 관리한다.
