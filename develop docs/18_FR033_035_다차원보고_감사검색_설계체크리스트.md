# FR-033/035 다차원 보고·감사 검색 설계 체크리스트

## 완료 정의

- [x] 부서·위치·유형·상태·취득기간 필터를 함께 적용한다.
- [x] 필터 대상의 전체·가용·사용중·수리·분실·폐기대기·취득가를 집계한다.
- [x] 부서·위치·유형·상태별 건수와 취득가를 제공한다.
- [x] 화면과 CSV가 동일한 필터 정규화·SQL 조건을 사용한다.
- [x] CSV 다운로드는 권한을 검사하고 필터·행 수를 감사 로그에 기록한다.
- [x] 감사 로그는 행위·대상·작업자·기간·변경값·요청 ID를 검색한다.
- [x] USER 보고 접근과 비관리자 감사 접근은 403이다.

## 데이터 흐름

`필터 폼 → Nginx → 세션·CSRF/RBAC → reporting-service 정규화 → 매개변수 PostgreSQL 집계 → 차원별 표`

`같은 필터 → CSV → REPORT_EXPORTED(필터·행 수·요청 ID·IP)`

`감사 검색 → ADMIN RBAC → metadata JSON 포함 검색 → 최대 200건`

## 화면 설계

- 기존 보고서 페이지: 상단 필터, KPI, 총 취득가, 부서/위치/유형/상태 4개 표.
- 기존 감사 페이지: 행위·대상·작업자·기간·검색어 폼과 결과 원장.
- 색상만으로 상태를 전달하지 않고 텍스트와 숫자를 함께 표시한다.
- 도구·모델·프롬프트·내부 기능번호를 화면에 표시하지 않는다.

## 실패 기준

- 존재하지 않는 상태, 잘못된 달력 날짜, 역전 기간은 400.
- 타 조직 ID는 기존 조직 경계에서 403.
- 화면 결과와 CSV 조건이 다르거나 다운로드 감사 로그가 없으면 미완료.
