# FR-001~004 조직·사용자 설계 체크리스트

## 완료 정의

- [x] 법인·본부·부서·팀 유형과 부모 계층을 저장한다.
- [x] 비용센터와 기존 근무지(`locations`)를 조직 범위로 관리한다.
- [x] ADMIN 최근 재인증 뒤 사용자 초대를 생성·조회·취소한다.
- [x] 초대에 조직·소속·역할·데이터 범위를 고정한다.
- [x] SHA-256 해시 저장, 48시간 만료, 단회 수락을 강제한다.
- [x] 수락 시 사용자와 `user_role_scopes`를 원자적으로 생성한다.
- [x] 조직 변경과 무관하게 기존 자산·감사 이력은 갱신·삭제하지 않는다.

## 데이터·보안 설계

| 항목 | 기준 |
|---|---|
| 조직 유형 | CORPORATE, HEADQUARTERS, DEPARTMENT, TEAM CHECK |
| 부모 | 법인은 없음, 나머지는 같은 법인의 활성 조직, TEAM은 말단 |
| 초대 역할 | USER 또는 MANAGER |
| 범위 | ORGANIZATION 또는 DEPARTMENT; 부서 범위는 department_id 필수 |
| 토큰 | 256-bit 난수 원문은 응답 1회·URL fragment 전달, DB는 SHA-256만 저장 |
| 동시성 | 초대 행 `FOR UPDATE`, 사용자·범위·accepted_at·감사를 단일 트랜잭션 처리 |
| 중복 | 조직별 미처리 이메일 부분 유일 인덱스, 토큰 해시 전체 유일 |
| 인덱스 | organization_id, department_id, invited_by와 활성 만료 조회 |

## 화면 설계

- 기존 관리자 페이지: 조직 생성·조직 계층·초대 발급·초대 현황·사용자·Outbox를 서로 다른 블록으로 구성한다.
- 로그인 페이지: `#invitation=`이 있을 때 계정 활성화 폼으로 전환하고 완료 후 URL 토큰을 제거한다. fragment는 HTTP 요청·접근 로그에 포함되지 않는다.
- 파란 배경 공식 반전 로고와 밝은 배경 공식 컬러 로고 규칙을 유지한다.
- 기존 페이지별 컨셉 중 관리자 페이지를 계층·초대 중심으로 갱신하며 제작 메타데이터를 넣지 않는다.
