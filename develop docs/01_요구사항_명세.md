# 요구사항 명세

| ID | 요구사항 | 우선순위 | 완료 기준 |
|---|---|---:|---|
| AUTH-01 | 이메일·비밀번호 로그인/로그아웃 | P0 | BCrypt 검증, 세션 회전·폐기 |
| AUTH-02 | 로그인 실패 잠금 | P0 | 5회 실패 시 15분 잠금 |
| AUTH-03 | 역할 기반 권한 | P0 | USER/MANAGER/ADMIN 서버 검사 |
| INV-01 | 비품 CRUD·검색 | P0 | 코드 중복 방지, 검색/필터 |
| INV-02 | 수량 무결성 | P0 | 가용수량 0 미만 금지 |
| LOAN-01 | 대여 처리 | P0 | 트랜잭션으로 가용수량 감소 |
| LOAN-02 | 반납 처리 | P0 | 중복 반납 방지, 수량 복구 |
| DASH-01 | 현황 지표 | P0 | 전체/대여/연체/부족 표시 |
| AUDIT-01 | 감사 로그 | P1 | 누가·언제·무엇을 기록 |
| OPS-01 | PostgreSQL/Docker 3계층 | P0 | database → backend → frontend 순으로 healthcheck 후 기동 |
| FR-025 | 구매 요청 필수정보 | P1 | 품목·수량·금액·비용센터·필요일·사유를 서버가 검증한 초안 저장 |
| FR-026 | 발주·부분 입고 | P1 | 승인 구매요청을 한 번만 발주하고 누적수량 이내에서 부분/전량 입고 상태 계산 |
| FR-027 | 검수 후 자산 생성 | P1 | PASS에서만 입고수량만큼 개별 자산 생성, 중복 검수와 검수 전 배정 차단 |

## 비기능 요구사항

- 보안: CSRF, Helmet, HttpOnly/SameSite 쿠키, 입력 검증, 매개변수 SQL
- 성능: 목록 기본 50건, 검색 컬럼 인덱스, 대시보드 쿼리 1초 이내 목표
- 가용성: DB healthcheck, 앱 `/health` 제공
- 접근성: 키보드 탐색, 명시적 label, 4.5:1 대비, 상태를 색상만으로 표현하지 않음
- 개인정보: 최소 수집, 감사로그에 비밀번호·세션·민감정보 저장 금지

## 범위 제외

MVP에서는 SSO/MFA, 바코드 스캐너, 다중 사업장 재고 이동, 이메일 알림, 클라우드 자동배포를 제외하고 확장 항목으로 둔다.
