# FR-026/027 부분 입고·검수 설계 체크리스트

## 완료 정의

- [x] 승인된 구매요청만 한 번 발주한다.
- [x] 부분 입고 누적수량은 요청수량을 넘지 않는다.
- [x] 일부 입고는 `PARTIAL_RECEIVED`, 전량 입고는 `RECEIVED`다.
- [x] 검수 전에는 자산 행이 없어 배정 대상이 될 수 없다.
- [x] PASS에서만 입고 수량만큼 `AVAILABLE` 자산을 생성한다.
- [x] FAIL/CONDITIONAL은 자산을 생성하지 않는다.
- [x] 중복 검수와 중복 자산 연결을 PostgreSQL 유일 제약으로 차단한다.
- [x] 감사 로그와 outbox 이벤트를 같은 트랜잭션에 기록한다.

## 데이터 흐름

`승인 구매요청 → 발주 → 부분/전량 입고(검수대기) → 검수 → PASS: 개별 자산+이력 / 그 외: 반려`

## DB 변경

- `uq_purchase_orders_request`: 구매요청당 발주 1건
- `uq_inspections_receipt`: 입고당 검수 1건
- `inspection_assets(inspection_id, asset_id, unit_no)`: 검수와 생성 자산 추적
- `idx_receipts_purchase_order`, `idx_inspection_assets_asset`: FK 탐색 및 삭제 경로 보조

## 화면 설계

- 기존 요청함 한 페이지를 유지해 새 페이지/컨셉 누락을 만들지 않는다.
- 승인·발주 / 부분 입고 / 검수·자산화의 3열 운영 흐름을 표시한다.
- 검수 전 `배정 불가`, PASS 후 `개별 자산 생성`을 텍스트로 구분한다.
- 내부 기능번호, 생성 도구, 프롬프트 메타데이터는 표시하지 않는다.

## 실패·롤백 기준

- 누적수량 초과, 타 조직 접근, 미승인 발주, 중복 발주·검수는 트랜잭션을 롤백하고 4xx를 반환한다.
- 자산·연결·이력·감사·outbox 중 하나라도 실패하면 PASS 검수 전체를 롤백한다.
