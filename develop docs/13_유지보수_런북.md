# Phase 12 유지보수 런북

## 1. 일상 상태 점검

다음 명령은 애플리케이션을 변경하지 않는 읽기 전용 점검이다.

```powershell
$env:MAINTENANCE_BASE_URL='https://배포도메인'
$env:MAINTENANCE_DATABASE_URL='비밀저장소에서_주입'
npm.cmd run maintenance:check
```

출력에서 frontend/backend 200, 필수 테이블 5개, DB 크기, 사용자·비품·대여·감사 건수, 저재고·연체·만료 세션을 확인한다. 저재고와 연체는 애플리케이션 장애가 아니라 담당자 조치 항목이다.

## 2. PostgreSQL 백업

```powershell
npm.cmd run db:backup
```

백업은 `artifacts/backups` 아래 PostgreSQL custom format으로 생성되고 파일 크기와 SHA-256이 출력된다. 이 디렉터리는 Git에서 제외된다. 운영에서는 생성 즉시 암호화된 외부 백업 저장소로 전송하고 접근 기록을 남긴다.

## 3. 격리 복구 훈련

```powershell
npm.cmd run db:restore-drill -- "artifacts/backups/백업파일.dump"
```

스크립트는 다음 안전 경계를 강제한다.

- `artifacts/backups` 아래 파일만 입력 허용
- `seowon_inventory_restore_drill_<무작위값>` 형식의 신규 DB만 생성
- 원본과 복구본의 users/items/loans/audit_logs 및 필수 테이블 수 비교
- 성공·실패와 관계없이 스크립트가 생성한 임시 DB만 제거
- 운영 DB `seowon_inventory`에는 쓰기 작업을 수행하지 않음

## 4. 의존성·이미지 점검

```powershell
npm.cmd audit --omit=dev --audit-level=high
docker compose images
```

취약점이 있으면 영향 버전과 사용 경로를 확인한 Issue를 만들고 별도 branch에서 갱신한다. 자동 강제 업데이트 후 즉시 운영 배포하지 않는다. 단위·통합·배포 스모크를 모두 통과한 뒤 릴리스한다.

## 5. 장애 등급과 초기 대응

| 등급 | 예시 | 초기 대응 |
|---|---|---|
| P1 | 전체 접속/로그인 불가, DB 손상 의심 | 15분 내 확인, 변경 중지, 증거 보존, 롤백/복구 판단 |
| P2 | 핵심 기능 일부 실패, 5xx 5분간 5% 이상 | 영향 기능 제한, 최근 변경 확인, 수정 또는 롤백 |
| P3 | 저재고·연체·단일 사용자 오류 | 업무 담당자 배정, 정규 변경 흐름으로 처리 |

## 6. 변경·종료 기준

유지보수 변경도 Issue → branch → 구현 → 단위 테스트 → 통합 테스트 → 문서 갱신 → commit → PR을 따른다. health, 스모크, 오류율, DB 무결성 중 하나라도 기준 미달이면 종료하지 않는다. 복구 후 같은 검사를 재실행하고 원인·영향·발견/복구 시각·재발 방지 Issue를 남겨야 종료한다.
