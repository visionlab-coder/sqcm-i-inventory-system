# Phase 30~33 후속 운영 체인

판정일: 2026-08-08

## Goal framing

- 사용자: 개발 검토자, 보안·인프라·업무 책임자, 실제 UAT 참여자
- 문제: 저장소 기능은 완료됐지만 CI 런타임 경고와 실제 공급자·운영 전환·서명 증거가 분리돼 있다.
- 변화: 외부 권한이 필요한 일을 추정하지 않고, 준비·검증·승인을 자동 게이트로 연결한다.
- 성공 지표: CI 경고 제거, 운영 계약 자동검사 통과, 미승인 전환 차단, 실행 책임과 증거 위치 명확화
- 제외 범위: 사용자 승인 없는 공급자 계약·Secret 생성, DNS 변경, production 배포, 대리 서명

## 체인

1. Phase 30: 잔여 항목과 외부 권한 경계를 확정하고 메타프롬프트를 보존한다.
2. Phase 31: `checkout`·`setup-node`를 Node 24 기반으로 전환하고 CI를 통과시킨다.
3. Phase 32: 운영 manifest와 Secret 참조를 검증하고 실제 환경에서는 `--probe`로 TLS·OIDC·health·공급자 도달성을 확인한다.
4. Phase 33: Artifact·복구·migration·공급자·health·smoke·로그·rollback·UAT 9개 증거와 3개 책임자 승인을 모두 요구한다.

앞 Phase 실패 시 다음 Phase는 완료 처리하지 않는다. 템플릿 검증 통과는 실제 운영 승인으로 간주하지 않는다.
