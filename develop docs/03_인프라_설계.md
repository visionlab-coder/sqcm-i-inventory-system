# 인프라 설계

## 로컬·검토 환경

Docker Compose에 정확히 세 서비스를 둔다.

1. `frontend`: Nginx가 SPA 정적 파일을 제공하고 `/api/*`를 `backend:8080`으로 프록시한다. 호스트에는 `3000:80`만 공개한다.
2. `backend`: Express JSON API가 로그인, 세션, RBAC, CSRF, 도메인 규칙과 SQL 접근을 담당한다. Compose 내부 포트는 8080이며 운영 구성에서는 호스트에 공개하지 않는다.
3. `database`: PostgreSQL 16이 영속 볼륨 `postgres-data`를 사용한다. Compose 내부 포트는 5432이며 운영 구성에서는 호스트에 공개하지 않는다.

기동 순서는 `database healthy → backend healthy → frontend`이다. 헬스 엔드포인트는 프론트엔드 `/health`, 백엔드 `/api/health`이며 백엔드 헬스는 DB 연결까지 확인한다.

`compose.test.yaml`은 통합 테스트에만 DB 55432, 백엔드 58080 포트를 추가 공개한다.

## 설정과 보안

모든 비밀은 `.env` 또는 배포 플랫폼 Secret으로 주입한다. `.env`는 Git에서 제외한다. 운영은 HTTPS 종단 뒤에서 보안 쿠키를 사용하고, 충분히 긴 `SESSION_SECRET`과 최소 권한 DB 계정을 사용한다. 외부 공격면을 줄이기 위해 프론트엔드 외 서비스는 공개하지 않는다.

## 배포 흐름

빌드 → 단위·통합 테스트 → 이미지 빌드 → DB 백업 → 마이그레이션 → 세 서비스 배포 → health → 로그인·대시보드 핵심 기능 검사 → 로그 확인 → 성공 또는 이전 이미지·DB 백업으로 롤백한다.

## 관측

구조화 JSON 로그에는 request id, 경로, 상태 코드, 지연 시간, 인증된 사용자 ID를 남기고 비밀번호·세션·CSRF 값은 제외한다. API 응답의 `x-request-id`와 감사 로그의 `request_id`로 브라우저→API→DB 변경을 연결한다. 세 서비스 health, DB 용량, 5xx, 로그인 실패율, 연체 건수를 관찰한다.

## CI 품질 게이트

`.github/workflows/quality.yml`은 단위 검사와 Docker 3계층 통합 검사를 독립 Job으로 수행한다. 통합 검사는 필수 환경변수가 없으면 종료코드 2로 실패하므로 skip을 성공으로 오인하지 않는다. 실패 여부와 관계없이 Compose 상태·최근 로그를 남기고 테스트 볼륨을 정리한다.
