# Phase 26 FR-020 다단계 승인 설계

## 정책과 불변조건

- 조직·요청 유형·구매 금액 구간별 활성 정책을 우선순위로 선택한다.
- 정책은 1~10개의 순차 단계이며 각 단계는 MANAGER 또는 ADMIN 역할과 요청 부서/조직 범위를 가진다.
- 제출 시 정책과 단계를 요청별 승인 인스턴스로 복제해 이후 정책 변경이 진행 중 요청을 바꾸지 않는다.
- 현재 PENDING 단계 한 건만 행 잠금으로 처리한다. 요청자 자기 승인, 역할 불일치, 순서 건너뛰기, 중복 처리는 거부한다.
- 중간 승인은 요청을 SUBMITTED로 유지하고 최종 승인에서만 자산·배정·수리·폐기 업무를 반영한다.
- 반려는 현재 단계를 REJECTED, 후속 단계를 SKIPPED로 바꾸고 업무 데이터는 변경하지 않는다.

## 데이터 흐름

Browser 요청 제출 → Endpoint → Service가 정책 선택·승인 인스턴스 생성 → PostgreSQL. 승인자는 현재 단계 조회·역할/부서 검증 → 단계 이력 갱신 → 후속 단계 또는 최종 업무 반영 → 감사·Outbox → 응답.
