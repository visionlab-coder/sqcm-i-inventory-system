# FR-009/016 기준정보 생명주기 설계 체크리스트

## Goal Framing

- 사용자: 시스템 관리자, 자산 담당자
- 문제: 유형·모델·공급업체·위치가 시드/조회 중심이라 운영 변경 불가
- 변화: 관리자는 삭제 없이 기준정보를 운영하고 담당자는 활성 항목만 선택
- 성공 지표: 조직 범위 위반 0, 기존 자산 FK 손실 0, 4종 정상·실패 흐름 자동 검증
- 제외: 파일 첨부, 상태 전이 정책, 물리 삭제

## 계층·데이터 흐름

`Browser → /admin/references Endpoint → Controller → Reference Service → Reference Repository → PostgreSQL`

`PostgreSQL → Repository DTO → Service 결과 → Controller JSON → Browser 상태 갱신`

- Controller: URL·상태 코드·응답 키만 결정
- Service: ADMIN/RBAC, 조직 범위, 입력·부모·분류 규칙, 트랜잭션
- Repository: 4종 매개변수 SQL, 행 잠금, 감사 저장
- DB: FK·UQ·NOT NULL·활성 부분 인덱스

## 기능 인수 기준

| 기능 | 정상 | 실패·권한 | 데이터 |
|---|---|---|---|
| 목록 | ADMIN은 활성/비활성 전체, 업무 API는 활성만 | USER 403 | 필요한 열만 반환 |
| 생성 | 유형·모델·공급업체·위치 201 | 중복 409, 잘못된 부모/분류 409 | 생성+감사 COMMIT |
| 수정 | 명칭 수정 후 즉시 목록 반영 | 다른 조직 403, 빈 명칭 400 | before/after 감사 |
| 비활성 | 업무 선택지에서 제외 | 물리 DELETE 없음 | 기존 자산 FK 유지 |

## DB 변경

- `item_categories`: created_at, updated_at
- `item_models`: is_active, created_at, updated_at
- `vendors`: created_at, updated_at
- 활성 목록 쿼리에 맞춘 조직/분류 부분 인덱스와 누락 FK 인덱스
- 기존 001~005 checksum 불변, 006만 추가

## 화면 설계

- 기존 관리자 페이지 하단에 `REFERENCE DATA` 영역을 둔다.
- 생성 폼은 접힌 4개 블록으로 분리해 초기 우선 행동을 제한한다.
- 목록은 종류·코드·명칭·상태·수정/비활성 행동을 제공한다.
- 저장 중 버튼 비활성, 성공 알림, 실패 원인 표시, 빈 상태 문구를 제공한다.
- 기존 공식 로고와 색상 규칙을 유지하고 제작 메타데이터를 노출하지 않는다.
