# Phase 35~39 운영 보완 설계

데이터 흐름은 Browser → Endpoint → Controller → Service → Repository → PostgreSQL → 역방향 응답을 유지한다. 쓰기 요청은 same-origin·CSRF·RBAC·입력검증·멱등성·업무 트랜잭션·감사 순으로 처리한다.

운영 경계는 애플리케이션과 외부 공급자를 분리한다. 저장소는 HTTPS/OIDC/Secret/외부 저장·검사 계약과 fail-closed precheck를 제공하지만 실제 계정·인증서·Secret·서명은 운영 책임자가 공급한다.

검증 순서는 정적→단위→DB/통합→권한 역조건→브라우저→Docker health→부하·보안→장애복구→백업 복원→전환 게이트다. PostgreSQL 논리 백업 복구는 검증했으며 장기 운영의 시점복구(PITR)는 WAL 아카이빙과 운영 저장소가 추가로 필요하다.

참고 기준: OWASP CSRF Prevention Cheat Sheet, OWASP Logging Cheat Sheet, PostgreSQL 16 Continuous Archiving and Point-in-Time Recovery.
