# FR-009 상태·사유 기준정보 설계 체크리스트

## Goal Framing

- 사용자: 시스템 관리자, 자산 담당자
- 문제: 상태와 변경 사유가 코드·자유문자에 고정돼 조직별 표시·선택·추가 설명 정책을 운영할 수 없다.
- 변화: 관리자는 고정 상태 코드의 표시 정책과 사유 코드를 운영하고 담당자는 활성 정책만 사용한다.
- 성공 지표: 무효 상태·사유 사용 0, 조직 범위 위반 0, 상태 이력 유실 0
- 제외: 상태 전이 그래프 변경, 자동 워크플로 변경, 파일 첨부, 물리 삭제

## 설계 결정

- 상태 코드는 기존 `assets.status_code` CHECK 및 `STATUS_TRANSITIONS`와 동일한 15개만 허용한다.
- 관리자는 상태 코드 자체가 아니라 표시명·설명·정렬·활성 여부를 관리한다.
- 사유는 조직별 코드·명칭·적용 상태·추가 설명 요구 여부·활성 여부를 관리한다.
- 수동 상태 변경만 활성 상태·사유 정책을 강제한다. 승인 등 자동 워크플로의 상태 전이는 기존 업무 규칙을 유지한다.
- 상태 이력은 `reason_definition_id` FK와 당시의 표시 문구·추가 설명을 함께 저장해 기준정보 변경 후에도 과거 의미를 보존한다.
