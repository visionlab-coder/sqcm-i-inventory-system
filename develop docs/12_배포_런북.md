# Phase 11 배포 런북

## 1. 배포 단위

운영 배포는 Docker Compose의 세 서비스로 고정한다.

| 서비스 | 역할 | 운영 공개 |
|---|---|---|
| `frontend` | Nginx 정적 앱 및 `/api` reverse proxy | `FRONTEND_PORT`만 공개 |
| `backend` | Express API, 인증·권한·업무 규칙 | 내부 네트워크만 사용 |
| `database` | PostgreSQL 16 | 내부 네트워크만 사용 |

`compose.yaml`은 로컬 개발 기본값을, `compose.production.yaml`은 필수 비밀값·보안 옵션·로그 순환을 적용한다. 두 파일을 함께 사용해야 운영 구성이 된다.

## 2. 출시 준비

1. 검증된 Git commit SHA를 기록한다.
2. `.env.production.example`을 `.env.production`으로 복사한다.
3. 모든 예시값을 비밀 저장소에서 발급한 값으로 교체한다.
4. 외부 배포는 HTTPS 종단 구성을 확인하고 `COOKIE_SECURE=true`로 둔다.
5. 기존 PostgreSQL 백업과 복구 시험 결과를 확인한다.
6. `npm.cmd run check:full`이 skip 없이 통과한 commit만 배포한다.

```powershell
Copy-Item .env.production.example .env.production
notepad .env.production
node scripts/deploy-precheck.mjs .env.production
```

`.env.production`은 Git 추적 대상이 아니다. 터미널, 로그, 보고서에 비밀값을 출력하지 않는다.

## 3. 배포

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy.ps1 `
  -EnvFile .env.production `
  -ProjectName seowon-inventory
```

스크립트는 사전검사 → Compose 렌더링 검사 → 빌드·기동·health 대기 → 스모크 테스트 → 상태 출력 순서로 실행한다. 스모크 검사는 프런트 health, API health, 익명 접근 401, 공식 반전 로고 응답을 검사한다.

## 4. 배포 성공 기준

- `frontend`, `backend`, `database`가 모두 `healthy`
- `/health`, `/api/health`가 200
- 인증 없는 `/api/items`가 401
- 공식 반전 로고가 200 및 이미지 Content-Type
- backend·database 호스트 포트가 공개되지 않음
- 오류 로그 급증이 없고 비밀값이 로그에 없음

## 5. 상태와 로그

```powershell
docker compose --env-file .env.production -p seowon-inventory `
  -f compose.yaml -f compose.production.yaml ps
docker compose --env-file .env.production -p seowon-inventory `
  -f compose.yaml -f compose.production.yaml logs --tail 100
$env:DEPLOY_BASE_URL='https://배포도메인'
npm.cmd run deploy:smoke
```

## 6. 롤백

health 실패, 핵심 스모크 실패, 5xx 급증, 인증 장애 또는 DB 호환성 문제가 하나라도 있으면 신규 트래픽을 중단한다. `.env.production`의 `RELEASE_TAG`를 직전 검증 이미지 태그로 되돌린 뒤 다음을 실행한다.

```powershell
docker compose --env-file .env.production -p seowon-inventory `
  -f compose.yaml -f compose.production.yaml up -d --no-build --wait
npm.cmd run deploy:smoke
```

DB 변경이 포함된 릴리스는 하위 호환 migration을 원칙으로 한다. 역호환이 불가능하면 임의 SQL로 되돌리지 않고, 사전에 복구 시험을 마친 백업과 승인된 복구 절차를 사용한다. 원인·영향·발견 시각·조치·복구 시각을 이슈에 남긴다.

## 7. 현재 배포 경계

로컬 Docker 3계층의 재현 가능한 운영 패키지와 릴리스 리허설까지 완료했다. 실제 외부 공개는 서버·도메인·TLS·비밀 저장소·백업 위치가 지정된 뒤 같은 런북으로 수행한다.
