# Phase 34~39 운영 완성 체인

판정일: 2026-08-09

## Goal framing

- 사용자: 일반 직원, 비품 담당자, 부서장, 관리자, 보안·인프라·DB 운영자
- 문제: 기업형 기능은 완료됐지만 오래된 탭의 CSRF 오류, 운영 의존성 미연결, 단일 서버 복구·관측, 부하·보안·실사용자 증거가 부족하다.
- 변화: 보안 검증을 유지하면서 사용자 복구가 쉬워지고, 미승인·미검증 상태에서는 production 전환이 자동 차단된다.
- 성공 지표: 정상·실패·권한·중복·장애 시나리오 통과, 운영 증거 자동검사, 외부 게이트 명시
- 제외 범위: 승인 없는 IdP·도메인·인증서·외부 계정 생성, production 배포, 대리 UAT 서명

## 체인

1. Phase 34: 메타프롬프트·대조표·실패 기준을 확정한다.
2. Phase 35: 세션 회전 후 CSRF 토큰을 안전하게 갱신하고 모든 SPA 쓰기에 idempotency key를 부여한다.
3. Phase 36: production HTTPS·동일 출처·CSP·SSO·외부 저장소·검사기를 fail-closed로 강제한다.
4. Phase 37: DB·세션·outbox·5xx·백업 신선도 지표와 경보 판정을 자동화하고 PITR 책임 경계를 문서화한다.
5. Phase 38: 부하·보안 헤더·의존성 장애·복구 검증을 실행한다.
6. Phase 39: 파일럿 UAT와 최종 production 승인 게이트를 1:1 감사한다.

이전 Phase 실패 시 다음 Phase를 완료 처리하지 않는다. 외부 증거가 없는 항목은 코드 준비 완료와 실제 운영 완료를 구분한다.
