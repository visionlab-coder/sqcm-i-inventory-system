# Phase 60~64 최종 보완 체인 메타프롬프트

ROLE:
대기업 현장 자산 Cost Control 제품의 시니어 제품·보안·품질 엔지니어

GOAL:
이중 원장을 단일 기업 자산 원장으로 전환하고, 관리자 업무 흐름·Cost ROI·AI 평가/피드백·브라우저 접근성·역할별 UAT를 연결해 파일럿 가능한 기준을 만든다.

USERS:
현장 직원, 부서 관리자, 조직 관리자, 시스템 관리자, Cost/재무 담당자

CONTEXT:
제품 포지션은 “새로 구매하기 전에 다른 현장의 유휴 자산을 찾아 이동시키고, 구매·수리·교체 중 가장 비용이 낮은 행동을 추천하는 AI 현장 자산 Cost Control”이다. AI보다 데이터 원장 통합을 우선한다.

SCOPE:
Phase 60 단일 `assets` 원장과 조직 범위 대시보드; Phase 61 관리자/구매 단계형 화면과 처리 사유; Phase 62 외부 AI/OCR provider 계약·추천 피드백·평가 원장; Phase 63 절감 이벤트·ROI·예산·공급사·활용률; Phase 64 공유 UI 컴포넌트·접근성·반응형 계약·역할별 API UAT·브라우저 스모크.

OUT OF SCOPE:
실제 외부 AI 공급자 계약·모델 학습, 운영 DNS/TLS 연결, ERP/구매 시스템 실시간 연동, 실제 현장 사용자 서명 UAT, 운영 백업 복구 훈련은 별도 승인 게이트로 남긴다.

CONSTRAINTS:
기존 AGENTS.md·CLAUDE.md·agent docs·global instructions를 보존한다. Controller에 SQL을 추가하지 않는다. 모든 조회·변경은 조직/부서 범위를 Service에서 재검사한다. 운영 AI는 `AI_PROVIDER_DRIVER=external`만 허용한다.

TOOLS:
Node.js, PostgreSQL Docker Compose, Node test runner, UI contract checker, in-app browser skill

WORKFLOW:
1. 기존 원장과 권한 범위를 확인한다.
2. 마이그레이션과 Service/Repository/API를 구현한다.
3. 화면 상태·접근성·모바일 계약을 구현한다.
4. 단위 → UI contract → Docker integration → migration verify → browser smoke 순으로 검증한다.
5. Phase별 보고서와 이 체인 결과를 `docs/phase-reports` 및 `agent docs`에 기록한다.

SUCCESS CRITERIA:
81개 JavaScript syntax 검사, 97개 단위 테스트, UI contract 13개, Docker 통합 20개, migration 22/22가 통과한다. 브라우저에서 canonical dashboard·Cost positioning·모바일 메뉴 접근성·콘솔 오류 0건을 확인한다.

FAILURE CRITERIA:
구형 원장 API가 프런트에서 호출되거나, 타 조직 데이터가 노출되거나, AI 결과에 evidence/confidence/피드백 원장이 없거나, 저장된 UI 번들이 HTML fallback을 반환하거나, 핵심 테스트가 실패하면 완료로 보고하지 않는다.

OUTPUTS:
Phase 60~64 코드·마이그레이션·테스트·Phase별 완료 보고서·최종 보완 체인 보고서

VERIFICATION:
`npm.cmd run check`, `npm.cmd run ui:contract`, Docker `npm.cmd run test:integration`, `npm.cmd run db:verify`, 브라우저 스모크 및 정적 번들 Content-Type 확인

MEMORY UPDATE:
실제 테스트 수·마이그레이션 버전·브라우저 viewport·미완료 운영 게이트를 기록한다. 비밀값은 기록하지 않는다.

STOP CONDITION:
동일 원인의 실패가 3회 반복되거나 외부 공급자·운영 권한 없이는 검증할 수 없는 게이트에 도달하면 구현을 멈추고 해당 증거와 승인 필요사항을 보고한다.
