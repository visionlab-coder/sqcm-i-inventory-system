# 웹개발 프로세스 전역지침

## 1. 개발 순서

프로젝트 폴더 → Docs → 요구사항 → 기능 설계 → 인프라 설계 → DB 설계 → 화면 설계 → 기능 개발 → 단위 테스트 → 통합 테스트 → 배포 → 유지보수 순서를 따른다.

## 2. 단계별 통제

### 1단계: 프로젝트 폴더

- 프로젝트 루트와 실행 방법을 확인한다.
- 소스·DB·테스트·문서·목업 위치를 분리한다.
- 기존 파일과 사용자 변경을 보존한다.

### 2단계: Docs

- Client Docs, Developer Docs, Agent Docs를 분리한다.
- Agent.md 또는 AGENTS.md의 정확한 파일명을 확인한다.
- 문서 간 우선순위와 충돌 처리 규칙을 기록한다.

### 3단계: 요구사항

각 요구사항에 ID를 부여한다.

요구사항에는 사용자, 문제, 입력, 처리, 출력, 권한, 정상 조건, 실패 조건, 인수 기준, 제외 범위를 포함한다.

### 4단계: 기능 설계

- 기능을 작은 단위로 분해한다.
- 모르는 부분은 선택지와 장단점을 제시한다.
- 결정되지 않은 기능을 임의로 확정하지 않는다.
- 기능·인프라·DB·화면 설계의 상호 영향을 검토한다.

### 5단계: 인프라 설계

- local, dev, staging, production을 구분한다.
- 포트·네트워크·Secret·DB·파일 저장소를 정의한다.
- healthcheck, 로그, 백업, 롤백을 설계한다.
- 운영 환경에 공개할 포트를 최소화한다.

### 6단계: DB 설계

- 테이블·컬럼·자료형·PK·FK·UNIQUE·CHECK·INDEX를 정의한다.
- 변경 이력과 감사 로그를 설계한다.
- DB 마이그레이션 버전을 관리한다.
- 애플리케이션 규칙과 DB 제약조건을 함께 사용한다.

### 7단계: 화면 설계

컨셉아트 → HTML Mock → 브라우저 프리뷰 → 사용성 검토 → API 연결 순서를 지킨다.

### 8단계: 기능 개발

- 설계 문서를 체크리스트로 변환한다.
- 한 번에 한 기능만 구현한다.
- 기능 구현과 단위 테스트를 같은 작업 단위로 수행한다.
- Controller에 업무 로직과 SQL을 넣지 않는다.

### 9단계: 단위 테스트

- 정상·실패·권한·경계값을 검증한다.
- 기능 개발이 끝난 뒤 한 번에 작성하지 않는다.
- 실패한 테스트는 원인과 수정 내용을 남긴다.

### 10단계: 통합 테스트

- 여러 계층이 연결되는지 확인한다.
- DB·API·인증·권한·화면 흐름을 함께 검증한다.
- 기능별 완료 후 전체 핵심 흐름을 회귀 테스트한다.

### 11단계: 배포

빌드·테스트 → 이미지 또는 Artifact 생성 → DB 백업 → 마이그레이션 검토 → 배포 → Health Check → 핵심 기능 Smoke Test → 로그 확인 순서를 따른다.

### 12단계: 유지보수

운영 중 반복 문제와 사용자 피드백을 다음 요구사항·개선 백로그로 환류한다.

## 3. 브랜치 작업 흐름

Issue → feature branch → 작은 기능 구현 → 단위 테스트 → 문서 갱신 → commit → Pull Request → 리뷰 → merge 순서를 사용한다.

main 브랜치는 가능한 한 배포 가능한 상태를 유지한다.

## 4. 완료 상태

다음 조건을 모두 만족해야 단계 또는 기능을 완료로 표시한다.

- 요구사항 ID가 있다.
- 설계 문서가 있다.
- 구현 코드가 있다.
- 정상·실패·권한 테스트가 있다.
- 감사·로그·오류 처리가 있다.
- 문서와 코드가 일치한다.
- 실제 실행 결과가 있다.
