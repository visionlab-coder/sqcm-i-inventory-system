## 2. 에이전트 작업 규칙

- 작업을 시작하기 전에 관련 문서와 현재 상태를 읽는다.
- 목표·범위·성공·실패 기준을 먼저 보고한다.
- 모르는 것은 질문·선택지·영향으로 분리한다.
- 한 번에 한 기능 또는 한 단계만 처리한다.
- 사용한 도구와 실행 명령을 명시한다.
- 작업 후 파일·테스트·로그로 결과를 증명한다.
- 자신이 하지 않은 일을 했다고 주장하지 않는다.
- 도구가 할 수 없는 일을 할 수 있다고 말하지 않는다.
- 위험한 작업은 대상과 범위를 확인하고 중단 기준을 둔다.

## 3. 멀티 에이전트

여러 에이전트를 사용할 때 역할을 분리한다.

- 요구사항 분석자
- DB 설계자
- 백엔드 개발자
- 프론트엔드·UI 개발자
- 테스트·보안 검토자
- 배포·운영 담당자

각 에이전트는 자신의 변경 범위와 산출물을 명확히 한다. main 또는 기준 브랜치에 직접 충돌하는 변경을 하지 않는다.

## 5. 테스트 실패 처리

실패를 다음 계층으로 분류한다.

- 입력·검증
- 인증·권한
- Controller·Endpoint
- Service·비즈니스 규칙
- Repository·SQL
- Database·마이그레이션
- 인프라·컨테이너
- 브라우저·CSS·JS

재현 → 원인 확인 → 최소 수정 → 관련 테스트 → 전체 핵심 흐름 순으로 진행한다.

## 6. 메모리 파일

권장 파일:

- 현재 상태
- 결정 로그
- 작업 큐
- 테스트 현황
- 배포·운영 런북

다음 에이전트가 현재 상태를 빠르게 파악할 수 있도록 각 파일을 짧고 최신 상태로 유지한다.

## 7. 종료 기준

다음 중 하나가 충족되면 해당 작업을 종료한다.

- 성공 기준을 모두 통과했다.
- 미결정 사항 때문에 진행할 수 없으며 질문을 남겼다.
- 같은 원인의 실패를 3회 반복해 증거와 중단 사유를 보고했다.

성공하지 않았는데 시간·토큰 부족만으로 완료 처리하지 않는다.
