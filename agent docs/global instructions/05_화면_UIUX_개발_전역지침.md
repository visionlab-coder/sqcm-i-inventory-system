# 화면·UI/UX 개발 전역지침

## 1. 디자인 시스템 8요소

화면 설계는 다음 순서로 결정한다.

1. 브랜드 아이덴티티
2. 제품의 성격
3. 디자인 유형
4. 색상 팔레트
5. 대표 그래픽·폰트
6. 레이아웃·간격
7. 컴포넌트
8. 반복되는 패턴

AI에게 예쁘게 해달라고만 요청하지 않는다. 위 8요소를 먼저 정의한다.

## 2. 화면 제작 순서

컨셉아트 → HTML Mock → 브라우저 프리뷰 → 사용성 검토 → 실제 API 연결 순서로 진행한다.

프리뷰에서 다음을 확인한다.

- 화면의 목적이 첫눈에 보이는가
- 핵심 행동이 명확한가
- 빈 상태·로딩·오류 상태가 있는가
- 권한 없는 기능이 노출되지 않는가
- 모바일·데스크톱에서 사용할 수 있는가

## 3. 공통 컴포넌트

다음 요소는 일관된 디자인 토큰과 동작을 사용한다.

- 헤더
- 사이드바 또는 모바일 메뉴
- 페이지 제목
- breadcrumb
- 검색·필터
- 테이블
- 버튼
- 입력·검증 메시지
- 모달
- 상태 배지
- 알림
- 로딩·빈 상태·오류 화면

## 4. 사용성 원칙

- 첫 화면의 우선 행동은 3개 이하로 제한한다.
- 오류는 원인과 해결 방법을 함께 표시한다.
- 저장 중 중복 제출을 막는다.
- 위험한 작업은 확인·사유·취소를 제공한다.
- 상태를 색상만으로 표현하지 않는다.
- 테이블은 핵심 열을 우선하고 열 선택을 제공한다.
- 모바일에서는 조회·스캔·대여·반납을 우선한다.
- 사용자가 다음에 해야 할 행동을 항상 알 수 있게 한다.

## 5. 접근성

- 모든 입력에 명확한 label을 제공한다.
- 키보드 포커스와 순서를 확인한다.
- 충분한 색상 대비를 사용한다.
- 아이콘만으로 의미를 전달하지 않는다.
- 오류를 입력 요소 근처와 요약 영역에 함께 표시한다.
- 스크린리더가 상태와 버튼 목적을 이해할 수 있게 한다.

## 6. 화면과 데이터

- 화면에서 상태값을 임의로 저장하지 않는다.
- API 응답의 성공·실패·로딩 상태를 처리한다.
- 권한은 서버 기준이며 화면은 그 결과를 표현한다.
- 화면에 표시되는 목록과 DB 데이터의 기준 시점을 명시한다.
- 실제 업무 목적과 무관한 장식 요소가 핵심 정보를 가리지 않게 한다.
