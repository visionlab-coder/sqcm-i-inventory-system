# 로그인·보안·권한 전역지침

## 1. 인증과 인가

- 인증은 사용자가 누구인지 확인하는 과정이다.
- 인가는 인증된 사용자가 무엇을 할 수 있는지 확인하는 과정이다.
- 로그인 성공만으로 모든 기능을 허용하지 않는다.
- UI에서 메뉴를 숨겨도 API와 Service에서 권한을 재검사한다.

## 2. 로그인 흐름

1. CSRF 또는 동일 출처 보호 확인
2. 입력 형식 검증
3. IP·계정 속도 제한 확인
4. 계정 잠금 확인
5. 사용자 조회
6. 비밀번호 해시 비교
7. 실패 횟수 증가 또는 성공 처리
8. 성공 시 세션 ID 회전
9. 최소 세션 정보 저장
10. 역할·조직 범위 조회
11. 감사 로그 기록
12. 허용된 화면으로 이동

존재하지 않는 계정 여부가 드러나지 않도록 오류 메시지를 일반화한다.

## 3. 세션

- 세션 ID를 로그인 성공 시 교체한다.
- 로그아웃 시 서버 세션과 쿠키를 모두 무효화한다.
- 만료된 세션으로 보호 API에 접근하면 401을 반환한다.
- 세션 쿠키는 HttpOnly, Secure, 적절한 SameSite를 사용한다.
- 세션 원문은 로그에 남기지 않는다.
- 세션에 저장하는 정보는 최소화한다.

## 4. 비밀번호·계정 보호

- 비밀번호 평문 저장 금지
- BCrypt 또는 조직이 승인한 강한 해시 사용
- 로그인 실패 횟수와 잠금 시각 관리
- 초기 정책은 5회 실패 시 15분 잠금과 같이 명시
- 비밀번호 재설정 토큰은 단회성·만료·안전한 저장
- 계정 열거 방지
- 운영 계정과 테스트 계정 분리

## 5. 권한

권한은 사용자 → 역할 → 기능 권한 → 조직 범위 순으로 계산한다.

예시 역할:

- USER: 조회·본인 업무
- MANAGER: 비품 등록·수정·대여·반납
- ADMIN: 사용자·감사·정책 관리

권한 검사는 최소한 다음에서 수행한다.

- 라우트 또는 Controller
- Service의 업무 규칙
- DB 조회의 조직 범위 조건

## 6. 보안 로그

다음 행위는 감사한다.

- 로그인 성공·실패
- 계정 잠금·해제
- 로그아웃
- 비밀번호 변경
- 역할·권한 변경
- 자산 등록·수정
- 대여·반납
- 승인·반려
- 삭제·폐기
- 보고서·CSV 다운로드

감사 로그에는 행위자·시각·행위·대상·결과·요청 ID·IP·변경 전후를 남기되 비밀번호·세션 원문·민감 비밀은 제외한다.
