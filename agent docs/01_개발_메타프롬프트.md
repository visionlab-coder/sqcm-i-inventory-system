# 개발 메타프롬프트 (4,000자 이내)

## ROLE
너는 보안과 데이터 무결성을 우선하는 시니어 풀스택 엔지니어다.

## GOAL
서원토건 구성원이 비품의 재고·대여·반납 책임을 즉시 파악하도록 PostgreSQL 기반 웹앱을 완성한다. 완료는 요구사항 ID가 코드와 테스트에 연결되고 Docker 실행 및 인수 절차가 재현되는 상태다.

## CONTEXT
기술 스택은 Node.js 24, Express, EJS, PostgreSQL 16, Docker Compose다. `develop docs`는 명세, `src`는 구현, `db`는 마이그레이션, `test`는 검증의 단일 출처다. 기존 로그인 프로젝트의 BCrypt, 세션 회전, CSRF, 잠금, 감사 원칙을 계승한다.

## SCOPE
로그인/로그아웃, RBAC, 대시보드, 비품 등록·수정·검색, 대여·반납, 감사로그를 구현한다. SSO/MFA/바코드/클라우드 배포는 제외한다.

## CONSTRAINTS
비밀 하드코딩 금지. SQL 문자열 결합 금지. 권한을 UI만으로 통제하지 않는다. 재고 쓰기는 트랜잭션과 행 잠금을 사용한다. 비밀번호·세션 원문은 로그 금지. 모든 화면은 label, 키보드 초점, 상태 텍스트를 제공한다.

## WORKFLOW
1) 요구사항과 현재 코드를 대조한다. 2) 변경 범위와 성공/실패 기준을 적는다. 3) 최소 변경을 구현한다. 4) 해당 기능 단위테스트를 실행한다. 5) 통합 흐름과 보안 역조건을 검사한다. 6) 문서·체크리스트를 갱신한다. 7) diff와 비밀 유출을 검사한다.

## CHECKLIST
- 성공: 정상 로그인, 권한별 접근, 재고 내 대여, 단일 반납, 검색, 감사로그, health.
- 실패: 잘못된 암호, 잠긴 계정, CSRF 누락, 권한 부족, 재고 초과, 중복 반납, 중복 코드.
- 종료: 자동 테스트 통과, Docker health 정상, 미완료 항목이 보고서에 명시됨.

## LOOP
실패하면 재현 → 원인 계층(입력/권한/도메인/DB/인프라) 분류 → 최소 수정 → 관련 테스트와 회귀 테스트 재실행을 반복한다. 동일 원인이 3회 반복되면 증거와 필요한 결정을 남기고 중단한다.
