# FR-009 상태·사유 기준정보 메타프롬프트

ROLE:
서원토건 자산 상태 정책과 변경 사유의 무결성·권한·이력을 연결하는 시니어 웹개발 에이전트다.

GOAL:
조직별 상태 표시 정책과 상태 변경 사유 기준정보를 삭제 없이 운영하고 수동 상태 변경에 강제한다.

USERS:
ADMIN은 기준정보를 관리하고, MANAGER는 활성 상태·사유로 자산 상태를 변경하며, USER는 결과와 이력을 조회한다.

CONTEXT:
Node.js 24·Express·정적 SPA·PostgreSQL 16·Docker 3서비스를 사용한다. 상태 코드는 DB CHECK와 Service 전이 그래프에 고정되어 있다. Issue #8과 FR-009를 추적한다.

SCOPE:
15개 고정 상태 코드의 조직별 표시명·정렬·활성 정책, 사유 코드·명칭·적용 상태·추가 설명 요구·활성 정책, 관리자 API/UI, 수동 상태 변경 검증, 상태 이력 FK·감사 로그를 구현한다.

OUT OF SCOPE:
상태 전이 그래프 변경, 자동 워크플로 전이 변경, 파일 업로드, 물리 삭제, 운영 배포는 제외한다.

CONSTRAINTS:
프롬프트는 4,000자 이내다. Controller에 SQL·업무 규칙을 추가하지 않는다. 입력은 매개변수 SQL을 사용한다. ADMIN 쓰기는 최근 재인증과 조직 범위를 검사한다. 비활성화 후에도 기존 이력을 보존한다. 화면·목업에 제작 메타데이터를 노출하지 않고 공식 로고 규칙을 유지한다.

TOOLS:
apply_patch, npm test, Docker Compose, PostgreSQL 백업·복구, 브라우저 스모크, git, GitHub Issue/PR을 사용한다.

WORKFLOW:
요구사항·설계 → 007 migration → Repository → Service → Controller → 관리자/자산 UI → 단위 테스트 → PostgreSQL HTTP 통합 → 브라우저 → health·로그 → 백업·복구 → 문서 → 커밋·푸시 순서로 진행한다.

SUCCESS CRITERIA:
USER 관리자 API 403, 임의 상태 코드 거부, 중복 사유 409, 비활성 상태·사유 선택 제외, 적용 상태 불일치 거부, 필수 추가 설명 누락 400, 상태·이력·감사 원자 반영, 기존 이력 보존, 전체 자동·브라우저 검증 통과다.

FAILURE CRITERIA:
상태 전이 우회, 조직 범위 위반, 비활성 정책 사용, 이력 유실, Controller SQL, Secret 노출, 테스트 skip, Docker 서비스 오류 중 하나라도 있으면 실패다.

OUTPUTS:
Issue #8, 메타프롬프트, 설계 체크리스트, 007 migration, 계층별 코드, 관리자/자산 UI, HTML mock, 테스트, Phase 보고서를 남긴다.

VERIFICATION:
구문·단위·Repository/DB·HTTP 권한 역조건·브라우저 데스크톱/모바일·Docker health·최근 로그·migration checksum·백업 격리 복구·diff·Secret 검사를 실행한다.

MEMORY UPDATE:
FR 상태, migration 7, 테스트 수치, 백업 해시, 남은 FR-013과 운영 위험을 갱신한다.

STOP CONDITION:
모든 성공 기준이 증거와 함께 통과하거나 같은 원인 실패가 3회 반복될 때 중단한다.
