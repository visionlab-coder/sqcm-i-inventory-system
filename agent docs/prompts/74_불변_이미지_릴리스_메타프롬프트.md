# Phase 74 불변 이미지 릴리스 메타프롬프트

## ROLE
서원토건 비품관리시스템의 코드부터 운영까지를 검증하는 릴리스 엔지니어다.

## GOAL
검증한 Git SHA와 실제 배포 이미지가 동일하도록 frontend/backend 이미지를 GHCR에 발행하고, production 배포가 그 SHA 이미지 외에는 실행되지 않게 한다. 운영 서버·Secret·DNS·UAT 서명이 없으면 완료를 주장하지 않는다.

## USERS / EXPECTED CHANGE
- 검토자는 PR의 코드, CI, 이미지 SHA를 한 경로로 추적한다.
- 운영자는 서버에서 재빌드하지 않고 검증된 두 앱 이미지만 pull한다.
- 시스템은 database를 포함해 정확히 3개 컨테이너로 실행한다.

## CONTEXT / SOURCE OF TRUTH
우선순위는 현재 사용자 요구 → 승인 Client Docs → 프로젝트 설계 → AGENTS/Agent Docs → 선택 Skill → 실제 코드·GitHub 증거다. 현재 작업 브랜치와 PR #10을 보존한다. 주 Skill은 `bamsoft-code-to-production-8`, 외부 연결 판정은 `bamsoft-integration-preflight`다.

## SCOPE
1. GitHub Actions를 검증된 commit SHA로 고정한다.
2. main SHA별 frontend/backend 이미지를 GHCR에 build·push하고 provenance를 남긴다.
3. production은 `sha-<40자리 git sha>`와 서로 다른 공식 GHCR 저장소만 허용한다.
4. 외부 배포는 build 없이 pull 후 `frontend/backend/database` 3서비스를 기동한다.
5. 계약 단위 테스트, Compose 계약, 저장소 위생, 통합 테스트와 GitHub CI를 검증한다.
6. 증거를 Phase 보고서와 현재 상태 문서에 기록한다.

## OUT OF SCOPE
실제 대상이 확인되지 않은 운영 서버 설치·재시작, DNS 변경, OAuth·Secret 생성, Frosty 계정 추정, 사람 대신 UAT 서명은 하지 않는다.

## AUTHORITY / SAFETY
현재 브랜치의 최소 코드·문서 변경, 테스트, Docker 검증, commit·push·PR 갱신·병합, GitHub 저장소 보호 설정은 허용한다. 비밀번호·토큰·세션 원문을 출력·커밋하지 않는다. 배포 대상·계정·Secret이 없으면 fail-closed로 보류한다.

## WORKFLOW
`Inspect → 불변 이미지 계약 → 최소 변경 → 로컬 검증 → push → PR CI → merge → main 이미지 발행 → digest 확인 → 외부 게이트 보고`

한 Loop에는 하나의 측정 가능한 증거만 둔다. 같은 원인의 실패가 3회면 중단한다.

## SUCCESS CRITERIA
- 구문·단위·통합·Compose 3서비스·저장소 위생 검사가 PASS다.
- production 사전검사가 임의 태그·로컬 이미지·동일 저장소를 거부한다.
- PR의 필수 CI가 PASS하고 main에 병합된다.
- `sha-<병합 SHA>` frontend/backend 이미지와 provenance가 GHCR에 존재한다.
- main은 필수 CI 없이 직접 변경되지 않도록 보호된다.

## FAILURE CRITERIA
가변 태그 사용, 서버 재빌드, 4번째 서비스, 미고정 외부 Action, Secret 노출, 실패 CI 병합, 대상 없는 production 실행은 실패다.

## VERIFICATION / OUTPUTS
실제 명령·종료 결과·GitHub run·이미지 digest를 `docs/phase-reports/74_*`에 남긴다. 로컬 완료와 외부 미완료를 구분하고 다음 READY 1건을 제시한다.

## MEMORY / STOP
실제 상태가 바뀐 경우에만 `agent docs/Agent.md`와 `docs/current-state.md`를 갱신한다. 외부 식별자·자격증명·사람의 승인이 필요하면 사실과 필요한 입력을 보고하고 멈춘다.
