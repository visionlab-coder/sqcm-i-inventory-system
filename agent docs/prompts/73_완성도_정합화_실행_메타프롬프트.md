# Phase 73 완성도 정합화 실행 메타프롬프트

ROLE:
서원토건 비품관리 시스템의 전역지침 정합성, 3계층 Docker 계약, 보안 위생, 문서 정본과 검증 증거를 완성하는 시니어 웹개발 에이전트다.

GOAL:
PR #10의 기존 기능을 보존하면서 새 전역지침의 첫 번째 로컬 증거 공백부터 수정해, 정확히 3개 Docker 서비스와 최신 단일 상태 정본, 비밀 없는 공개 저장소, 재현 가능한 품질 게이트를 만든다. 외부 공급자·사용자 서명 없이 Production 완료를 주장하지 않는다.

USERS / EXPECTED CHANGE:
- 개발자와 검토자는 현재 정본·명령·증거·남은 게이트를 한 경로에서 찾는다.
- 운영자는 frontend/backend/database 3서비스만 배포하고 worker 업무를 backend 안에서 안전하게 수행한다.
- 공개 저장소 독자는 실제 또는 재사용 가능한 고정 비밀번호를 얻지 못한다.

CONTEXT:
- 브랜치 `agent/productization-completion-chain`, draft PR #10, CI 2종 PASS.
- 현재 구문 85개, 단위 101/101, UI 계약 13/13, migration 22개다.
- production Compose는 `automation-worker` 때문에 실효 4서비스로 3서비스 계약을 위반한다.
- 구형 프로젝트 지침과 상세 전역지침 복사본, 과거 검증 수치, legacy 메타프롬프트 56개가 새 계약과 혼재한다.
- 운영 결정 8건, UAT 19건, 실제 manifest·cutover evidence, 외부 AI 브리지는 미완료다.

SCOPE:
1. 프로젝트 AGENTS/CLAUDE를 프로젝트 차이·명령·금지·정본·Skill 라우팅 중심으로 경량화한다.
2. 기존 12단계 산출물을 `bamsoft-web-process-11`의 11단계 게이트에 매핑한다.
3. production Compose에서 별도 worker 컨테이너를 제거하고 backend 내부 실행 계약으로 통합한다.
4. 서비스 수 3개와 production 구성 불변식을 자동 검사한다.
5. 공개 파일의 고정 비밀번호를 환경변수·실행 시 생성 값·비밀 아닌 표식으로 교체한다.
6. 컨셉 폴더의 제작 프롬프트를 Agent Docs 아카이브 정본으로 이동하고 화면 산출물에서 제거한다.
7. 최신 수치와 legacy 문서·프롬프트 상태를 단일 현재상태 문서에 기록한다.
8. 관련 단위·통합·Docker·브라우저·Secret·diff 검증을 수행하고 PR을 갱신한다.

OUT OF SCOPE:
- 실제 운영 계정·Secret·OAuth 동의, DNS/TLS, production 배포·migration
- 외부 OIDC·저장소·검사기·이벤트·경보·AI 공급자 생성 또는 호출
- UAT 서명 대행, 기존 LM Studio·소놀봇의 비공식 호출
- main merge, 과거 Phase 증거의 삭제·전수 재작성

INPUTS / SOURCE OF TRUTH:
1. 현재 사용자 요구와 승인된 Client Docs
2. 현재 전역지침과 선택한 Skill
3. 프로젝트 AGENTS/CLAUDE, Agent Docs, Developer Docs
4. 실제 코드·Compose·Git·CI·DB·브라우저 결과
충돌 시 위 순서를 따르고 과거 문서는 역사 증거로만 보존한다.

WORKFLOW:
`Inspect → READY 1건 → 실패 기준 고정 → 최소 변경 → 관련 검증 → 증거 보고 → Memory 갱신`

Loop 순서:
1. 지침·정본 정합화
2. Docker 3서비스 복구와 계약 테스트
3. 자격증명·메타데이터 위생
4. 최신 추적·legacy 분류
5. 전체 로컬 검증과 Phase 보고
6. 승인된 현재 브랜치 commit·push·PR CI 확인

AUTHORITY / PERMISSIONS:
- 읽기·PowerShell·로컬 수정·테스트·Docker 개발 스택: 허용.
- 현재 작업 브랜치 commit·push와 기존 draft PR 갱신: 이번 사용자 요청 범위에서 허용.
- 삭제는 대체 정본과 Git 복구 가능성을 확인한 파일만 허용하며 대량·재귀 삭제는 금지한다.
- 운영·외부 계정·OAuth·Secret·DNS·배포·merge·reviewer 권한 변경은 별도 승인과 실제 입력이 필요하다.

CONSTRAINTS:
- frontend/backend/database 정확히 3서비스를 유지한다.
- Controller→Service→Repository/DB, RBAC·조직 범위·CSRF·트랜잭션을 약화하지 않는다.
- 기존 사용자 변경과 완료 산출물을 보존한다.
- 비밀번호·토큰·세션·운영 Secret을 출력·문서화·커밋하지 않는다.
- 한 Loop에는 측정 가능한 작업 하나만 둔다.

SUCCESS CRITERIA:
- 프로젝트 지침이 새 전역지침과 충돌하지 않고 상세 절차를 Skill 정본으로 참조한다.
- production 포함 Compose 실효 서비스가 정확히 3개이며 자동 테스트가 이를 강제한다.
- 고정 비밀번호 패턴과 Mock 제작 메타데이터 검사가 PASS한다.
- 현재 상태 문서가 85/101/13/22 이상의 재검증 결과와 외부 NO-GO 게이트를 구분한다.
- 구문·단위·통합·Docker health·핵심 smoke·브라우저·diff·Secret 검사가 PASS한다.
- PR #10 최신 SHA의 필수 CI가 PASS한다.

FAILURE CRITERIA:
