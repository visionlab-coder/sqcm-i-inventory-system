# PE-C4 직원 셀프서비스 실행 계약

기준일: 2026-09-04 KST

## 1. 목적

일반 직원이 모바일과 데스크톱에서 현재 자신에게 배정된 비품, 요청·수리·알림 상태를 한 화면에서 확인하고 반납·수리·분실 요청을 담당자 workflow에 제출한다.

## 2. 범위

- 현재 로그인 사용자에게 활성 배정된 자산 전용 조회 API
- 본인이 만든 요청·수리 접수와 본인 수신 알림 요약
- 반납 사진·상태·부속품, 수리·분실 사유를 포함한 빠른 요청 UI
- API 자기 자산 역검사, CSRF·idempotency, 감사·승인 workflow 연결
- 단위·전체·UI·PostgreSQL·실제 브라우저 검증

관리자 workflow 변경, 타인·타 부서 자산 조회, HR/ERP 연동, Production·staging 배포는 범위 밖이다.

## 3. 처리 방식

`타인 자산 역조건 → SELF 전용 service/API → 모바일 화면과 상태표 → 요청 workflow → 단위·통합·브라우저 → 증거 → exact allowlist Git 체크포인트` 순서로 C4 한 건만 수행한다.

## 4. 입력 정본

현재 사용자 요구, 프로젝트 지침, `develop docs/34_SQCM-i_C_제품고도화_로드맵.md`, 승인된 기존 요청·수리·알림 설계, 실제 코드·DB·테스트·브라우저 순이다.

## 5. 권한

로컬 코드·테스트·문서와 격리된 합성 사용자·자산·요청 생성 및 exact cleanup만 허용한다. Production·staging·실제 직원 데이터·계정·Secret·보호 서비스는 변경하지 않는다.

## 6. 성공·실패 기준

성공은 내 활성 배정만 표시되고 타인 자산은 표시 0·요청 HTTP 403이며, 반납·수리·분실 동작, 요청 상태·알림, 1440×900·390×844 화면과 전체 회귀가 PASS하는 것이다. 타인 자산 노출, workflow·감사 누락, 모바일 가로 넘침 또는 합성 데이터 잔존은 실패다.

## 7. 검증 증거

구문·단위·전체 PostgreSQL 통합, UI 계약, Compose 3서비스, migration 일치, 합성 USER 브라우저의 자기 자산/타인 자산 역조건·요청 제출·DB 감사와 화면 SHA-256을 사용한다.

## 8. 산출물

전용 service/API·실제 SPA·검증 실행기·테스트, `PE_C4_EMPLOYEE_SELF_SERVICE_EVIDENCE.json`, C4 7범주 체크리스트, 제품 로드맵·현재 상태와 exact allowlist Git 체크포인트다.
