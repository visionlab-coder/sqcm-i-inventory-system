## MP-01 — 프로젝트 전체 수행

### ROLE
너는 보안, 데이터 무결성, 인수 가능성을 우선하는 기업용 풀스택 엔지니어다.

### GOAL
서원토건 구성원이 비품의 입고·재고·대여·반납·감사 이력을 관리하는 PostgreSQL 웹 애플리케이션을 완성한다. 완료 상태는 요구사항이 코드와 테스트에 추적되고 Docker 실행과 검토 절차가 재현되는 것이다.

### CONTEXT
전역 순서 1) 프로젝트 폴더 2) Docs/client/develop/agent/Agent.md 3) 요구사항 4) 기능 5) 인프라 6) DB 7) 화면·콘셉트·HTML mock 8) 기능 체크리스트·개발 9) 단위 10) 통합 11) 배포 12) 유지보수를 따른다. 기존 로그인 프로젝트의 BCrypt, 세션 회전, CSRF, 잠금, 감사 원칙을 참고한다.

### CONSTRAINTS
PostgreSQL 사용. 비밀 하드코딩과 SQL 문자열 결합 금지. 권한은 서버에서 검사. 재고·대여·반납은 트랜잭션 처리. 모든 Phase 완료 시 보고서 작성. 프롬프트는 메타프롬프트 형식이며 항목별 4,000자 이내다.

### WORKFLOW
Goal framing → specification → context → harness → prompt → workflow → memory → verification loop 순으로 진행한다. Issue → branch → 구현 → 단위 테스트 → 문서 갱신·커밋 → PR 흐름을 유지한다.

### SUCCESS
1~12단계 문서, 동작하는 앱, 로그인·RBAC, DB 마이그레이션, 테스트, Docker, 화면 산출물과 Phase 보고서가 존재한다.

## MP-02 — 첨부 요구사항 비교와 체크리스트

### ROLE
너는 요구사항 누락과 충돌을 찾는 명세·품질 엔지니어다.

### GOAL
새로 제공된 전체 요구사항 문서와 직전 구현을 대조해 완료·부분·누락·충돌을 근거와 함께 분류한다. 콘셉트 아트는 단일 이미지가 아니라 페이지별로 존재해야 한다.

### INPUT
첨부 요구사항 문서, 기존 소스, Docs, 테스트, 화면 목업, 콘셉트 산출물.

### WORKFLOW
요구사항을 ID로 분해 → 파일과 테스트 증거 연결 → 상태 판정 → 기술 스택 충돌 기록 → 보완 우선순위 작성 → 페이지 목록과 콘셉트 수량 검증.

### CONSTRAINTS
근거 없는 완료 판정 금지. 권장사항과 필수사항 구분. 기존 사용자 변경 보존. 충돌은 임의로 숨기지 않고 선택지와 영향을 기록한다.

### OUTPUT
비교표, 기능·보안·DB·운영·화면 체크리스트, 페이지별 콘셉트 11종, 미완료 항목과 다음 작업 순서.

## MP-03 — Docker 3계층 분리

### ROLE
너는 컨테이너 경계와 최소 공개 원칙을 설계하는 인프라 엔지니어다.

### GOAL
Docker 서비스를 정확히 `frontend`, `backend`, `database` 세 개로 분리한다.

### ARCHITECTURE
frontend=Nginx 정적 SPA와 `/api` 프록시, backend=Express JSON API와 인증·업무 규칙, database=PostgreSQL 16과 영속 볼륨. 기동은 database healthy → backend healthy → frontend 순서다.

### CONSTRAINTS
운영 Compose는 frontend 3000만 공개한다. backend 8080과 database 5432는 내부 네트워크만 사용한다. 테스트 override에서만 58080과 55432를 공개한다. 기존 세션·CSRF·RBAC·트랜잭션 규칙을 유지한다.

### CHECK
Compose 서비스 수 3, 세 컨테이너 healthy, frontend `/health`, 프록시 `/api/health`, 로그인·대시보드, PostgreSQL 등록→대여→반납 통과.

### OUTPUT
Dockerfile, frontend Dockerfile/Nginx/SPA, compose.yaml, compose.test.yaml, 통합 테스트와 Phase 5·11 보고서.

## MP-04 — 서원토건 공식 로고 통일

### ROLE
너는 브랜드 원본의 무결성을 지키는 UI 시스템 담당자다.

### GOAL
사용자가 제공한 `SEOWON Since 1991` 이미지를 모든 UI 산출물의 공식 로고로 통일한다.

### CONSTRAINTS
로고 자형, 파랑·주황 색상, 비율, 문구를 재생성하거나 변경하지 않는다. 제공 PNG는 원본으로 보존한다. 표시용 자산은 투명 캔버스 여백만 제거한다. 임시 도형·워드마크 사용 금지. 대체 텍스트는 `SEOWON Since 1991`로 통일한다.

### SCOPE
SPA 로그인·사이드바, EJS 로그인·사이드바, HTML mock, 11개 콘셉트 페이지, Docker frontend 이미지, 브랜드 지침.

### CHECK
원본 파일 존재, 표시용 PNG 투명도 유지, 임시 `▰` 0건, 콘셉트 11/11, 브라우저 로그인·대시보드에서 실제 렌더링.

## MP-05 — Canva·Figma 레퍼런스 기반 UI 대폭 개편

### ROLE
너는 현장 업무와 브랜드 시스템을 함께 설계하는 엔터프라이즈 UX 디렉터다.

### GOAL
서원토건 공식 로고와 공통 토큰을 유지하면서 각 페이지의 업무 목적이 첫 3초 안에 구별되는 화면을 만든다. 획일적인 네이비 사이드바·둥근 흰 카드·동일 KPI 반복을 해체한다.

### REFERENCE
Canva의 크기·대비·3단계 타이포·여백 기반 시각 위계, Figma의 변수·토큰·컴포넌트·모드 기반 디자인 시스템과 대시보드 템플릿 다양성을 참고한다.

### PAGE ARCHETYPES
로그인=헤리티지 에디토리얼, 대시보드=비대칭 지휘판, 목록=카탈로그, 상세=도면 명세, 등록=스테퍼, 배정=스캔 키오스크, 요청=칸반, 실사=모바일 필드, 수리=타임라인, 보고서=편집 디자인, 관리자=권한 매트릭스.

### CONSTRAINTS
모든 페이지 동일 레이아웃 금지. 주황=조치, 청록=정보, 라임=진행. 한 화면에 강한 초점 하나. 공식 로고와 접근성, API 데이터 흐름, 기능은 유지한다. AI 래스터 나열 대신 검토 가능한 HTML/CSS 화면을 우선한다.

### CHECK
아키타입 11/11, 모바일 대응, 실제 로그인·대시보드·비품·대여 전환, 빈 화면·오류 오버레이 없음, 자동·통합 테스트 통과.

## MP-06 — 검증 루프

### ROLE
너는 기능과 시각 회귀를 함께 확인하는 QA 엔지니어다.

### GOAL
변경이 요구사항을 만족하면서 기존 인증·재고 무결성을 깨뜨리지 않았음을 증명한다.

### WORKFLOW
구문 검사 → 단위 테스트 → Docker 재빌드 → 세 health 확인 → 통합 테스트 → 실제 브라우저 로그인 → 핵심 메뉴 전환 → 스크린샷 → 임시 자산·오류 검사 → 문서 갱신.

### SUCCESS
단위 8/8, 통합 2/2, 세 컨테이너 healthy, 로그인·대시보드·비품·대여 렌더링, 공식 로고 로드, 콘셉트 11개 확인, `git diff --check` 통과.

### FAILURE LOOP
실패 증거를 저장하고 입력·권한·도메인·DB·인프라·브라우저로 원인을 분류한다. 최소 수정 후 관련 테스트와 전체 핵심 흐름을 다시 실행한다.

## MP-07 — GitHub 검토본 게시

### ROLE
너는 검토 가능성과 변경 추적성을 책임지는 릴리스 엔지니어다.

### GOAL
검증 완료 산출물을 의도별 단일 커밋으로 기록하고 GitHub `main`에 공유한다.

### WORKFLOW
`git status`로 범위 확인 → 비밀·임시 파일 검사 → 관련 파일만 stage → cached diff/check → 한국어 목적형 커밋 → origin main push → 작업 트리와 커밋 해시 확인.

### CONSTRAINTS
사용자 변경 삭제 금지. 비밀·세션·임시 파일 커밋 금지. 검증 실패 상태 푸시 금지. 외부 협업자 초대는 정확한 GitHub 사용자명과 권한이 확인된 경우에만 수행한다.

### OUTPUT
커밋 해시, 저장소 링크, 테스트 결과, 주요 문서와 화면 증거 경로.

## MP-08 — 컨셉아트·HTML mock 메타데이터 제거

### ROLE
너는 공개 산출물의 불필요한 제작 흔적과 파일 메타데이터를 제거하는 릴리스 정리 담당자다.

### GOAL
컨셉아트와 HTML mock에서 코딩·생성 과정이 드러나는 문구와 이미지 메타데이터를 모두 제거하되 화면 내용과 픽셀, 실행에 필요한 웹 표준 정보는 유지한다.

### SCOPE
`mock/concept`의 HTML·PNG와 `mock/html/index.html`. 제거 대상은 생성기·AI·레퍼런스·아키타입·날짜·페이지 수·mock 표기, PNG의 `caBX` 등 제작 출처 청크다.

### CONSTRAINTS
`charset`, `viewport`, 접근성 대체 텍스트와 실제 업무 데이터는 유지한다. PNG를 생성형으로 다시 만들지 않는다. 원본 해상도와 `IDAT` 이미지 데이터는 변경하지 않는다. 모든 임시 파일을 검증한 뒤 명시된 대상만 교체한다.

### CHECK
표시 메타데이터 검색 0건, PNG 12개 `caBX` 0건, 모든 PNG 로드·해상도 유지, 컨셉 11개와 HTML mock 브라우저 렌더링, `git diff --check` 통과.

### OUTPUT
정리된 HTML·PNG, 검증 기록, Phase 보고서와 GitHub 커밋.
