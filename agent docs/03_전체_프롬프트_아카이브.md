## MP-01 — 프로젝트 전체 수행

### ROLE
너는 보안, 데이터 무결성, 인수 가능성을 우선하는 기업용 풀스택 엔지니어다.

### GOAL
서원토건 구성원이 비품의 입고·재고·대여·반납·감사 이력을 관리하는 PostgreSQL 웹 애플리케이션을 완성한다. 완료 상태는 요구사항이 코드와 테스트에 추적되고 Docker 실행과 검토 절차가 재현되는 것이다.

### CONTEXT
전역 순서 1) 프로젝트 폴더 2) Docs/client/develop/agent/Agent.md 3) 요구사항 4) 기능 5) 인프라 6) DB 7) 화면·콘셉트·HTML mock 8) 기능 체크리스트·개발 9) 단위 10) 통합 11) 배포 12) 유지보수를 따른다. 기존 로그인 프로젝트의 BCrypt, 세션 회전, CSRF, 잠금, 감사 원칙을 참고한다.

### CONSTRAINTS
PostgreSQL 사용. 비밀 하드코딩과 SQL 문자열 결합 금지. 권한은 서버에서 검사. 재고·대여·반납은 트랜잭션 처리. 모든 Phase 완료 시 보고서 작성. 프롬프트는 메타프롬프트 형식이며 항목별 4,000자 이내다.

### WORKFLOW
Goal framing → specification → context → harness → prompt → workflow → memory → verification loop 순으로 진행한다. Issue → branch → 구현 → 단위 테스트 → 문서 갱신·커밋 → PR 흐름을 유지한다.

### SUCCESS
1~12단계 문서, 동작하는 앱, 로그인·RBAC, DB 마이그레이션, 테스트, Docker, 화면 산출물과 Phase 보고서가 존재한다.

## MP-02 — 첨부 요구사항 비교와 체크리스트

### ROLE
너는 요구사항 누락과 충돌을 찾는 명세·품질 엔지니어다.

### GOAL
새로 제공된 전체 요구사항 문서와 직전 구현을 대조해 완료·부분·누락·충돌을 근거와 함께 분류한다. 콘셉트 아트는 단일 이미지가 아니라 페이지별로 존재해야 한다.

### INPUT
첨부 요구사항 문서, 기존 소스, Docs, 테스트, 화면 목업, 콘셉트 산출물.

### WORKFLOW
요구사항을 ID로 분해 → 파일과 테스트 증거 연결 → 상태 판정 → 기술 스택 충돌 기록 → 보완 우선순위 작성 → 페이지 목록과 콘셉트 수량 검증.

### CONSTRAINTS
근거 없는 완료 판정 금지. 권장사항과 필수사항 구분. 기존 사용자 변경 보존. 충돌은 임의로 숨기지 않고 선택지와 영향을 기록한다.

### OUTPUT
비교표, 기능·보안·DB·운영·화면 체크리스트, 페이지별 콘셉트 11종, 미완료 항목과 다음 작업 순서.

## MP-03 — Docker 3계층 분리

### ROLE
너는 컨테이너 경계와 최소 공개 원칙을 설계하는 인프라 엔지니어다.

### GOAL
Docker 서비스를 정확히 `frontend`, `backend`, `database` 세 개로 분리한다.

### ARCHITECTURE
frontend=Nginx 정적 SPA와 `/api` 프록시, backend=Express JSON API와 인증·업무 규칙, database=PostgreSQL 16과 영속 볼륨. 기동은 database healthy → backend healthy → frontend 순서다.

### CONSTRAINTS
운영 Compose는 frontend 3000만 공개한다. backend 8080과 database 5432는 내부 네트워크만 사용한다. 테스트 override에서만 58080과 55432를 공개한다. 기존 세션·CSRF·RBAC·트랜잭션 규칙을 유지한다.

### CHECK
Compose 서비스 수 3, 세 컨테이너 healthy, frontend `/health`, 프록시 `/api/health`, 로그인·대시보드, PostgreSQL 등록→대여→반납 통과.

### OUTPUT
Dockerfile, frontend Dockerfile/Nginx/SPA, compose.yaml, compose.test.yaml, 통합 테스트와 Phase 5·11 보고서.

## MP-08 — 컨셉아트·HTML mock 메타데이터 제거

### ROLE
너는 공개 산출물의 불필요한 제작 흔적과 파일 메타데이터를 제거하는 릴리스 정리 담당자다.

### GOAL
컨셉아트와 HTML mock에서 코딩·생성 과정이 드러나는 문구와 이미지 메타데이터를 모두 제거하되 화면 내용과 픽셀, 실행에 필요한 웹 표준 정보는 유지한다.

### SCOPE
`mock/concept`의 HTML·PNG와 `mock/html/index.html`. 제거 대상은 생성기·AI·레퍼런스·아키타입·날짜·페이지 수·mock 표기, PNG의 `caBX` 등 제작 출처 청크다.

### CONSTRAINTS
`charset`, `viewport`, 접근성 대체 텍스트와 실제 업무 데이터는 유지한다. PNG를 생성형으로 다시 만들지 않는다. 원본 해상도와 `IDAT` 이미지 데이터는 변경하지 않는다. 모든 임시 파일을 검증한 뒤 명시된 대상만 교체한다.

### CHECK
표시 메타데이터 검색 0건, PNG 12개 `caBX` 0건, 모든 PNG 로드·해상도 유지, 컨셉 11개와 HTML mock 브라우저 렌더링, `git diff --check` 통과.

### OUTPUT
정리된 HTML·PNG, 검증 기록, Phase 보고서와 GitHub 커밋.

## MP-09 — 파란 배경의 공식 반전 로고 적용

### ROLE
너는 기업 CI 원본성과 화면 대비를 함께 관리하는 브랜드 UI 엔지니어다.

### GOAL
서원토건 공식 CI의 배경별 색상 활용 원칙에 따라 짙은 파랑·남색 배경에서 식별이 어려운 컬러 로고를 공식 반전형으로 교체한다.

### SOURCE
공식 CI 페이지 `https://www.seowonenc.co.kr/ci.html`과 공식 홈페이지 자산 `logo_w.png`를 기준으로 한다. 자산을 다시 그리거나 생성형 이미지로 복제하지 않는다.

### WORKFLOW
공식 출처와 파일 검증 → 로고가 놓인 모든 배경 분류 → 짙은 배경만 반전형으로 교체 → 밝은 배경 컬러형 유지 → 앱·EJS·HTML mock·컨셉 갤러리 확인 → Docker 재빌드 → 브라우저 시각 검증 → 문서·보고서 갱신 → GitHub 게시.

### CONSTRAINTS
로고 비율·문구·주황 포인트를 변경하지 않는다. CSS 필터로 임의 반전하지 않는다. 컨셉아트와 HTML mock에 제작도구·AI·프롬프트·파일 출처 메타데이터를 노출하지 않는다. 사용자 인증·재고 기능은 변경하지 않는다.

### SUCCESS
파란 배경의 로그인·사이드바·컨셉 헤더에서 공식 반전 로고가 선명하게 보이고, 밝은 배경의 컬러 로고는 유지된다. 관련 자산 요청 200, 단위·통합 테스트 통과, 세 Docker 컨테이너 healthy, `git diff --check` 통과.

## MP-10 — Phase 8 비품 CRUD 완성

### ROLE
너는 재고 무결성과 감사 가능성을 우선하는 기업용 자산관리 백엔드·프론트엔드 엔지니어다.

### GOAL
기존 등록·검색 기능에 비품 상세 조회, 수정, 논리 비활성화를 추가해 `INV-01 비품 CRUD·검색`을 완성한다.

### SCOPE
상세 화면은 현재 수량·위치·상태·최근 대여 이력을 제공한다. 수정 대상은 명칭·카테고리·위치·총수량·최소재고다. 비품 코드는 식별자이므로 변경하지 않는다. 삭제는 물리 삭제 대신 `INACTIVE` 전환으로 구현한다.

### CONSTRAINTS
MANAGER·ADMIN만 변경 가능하다. 총수량은 대여·분실 등을 포함한 현재 가용 제외 수량보다 작게 변경할 수 없다. 활성 대여가 있으면 비활성화를 거부한다. 변경·감사 로그는 하나의 PostgreSQL 트랜잭션으로 처리한다. CSRF·세션·기존 대여 흐름을 손상시키지 않는다.

### WORKFLOW
요구사항과 구현 대조 → 서비스 트랜잭션 구현 → 목적별 API 연결 → 상세·수정 UI 구현 → 기능별 정상·실패 테스트 → Docker 3계층 재빌드 → 브라우저 상세·수정 확인 → 문서·보고서 갱신 → GitHub 게시.

### SUCCESS
상세 조회, 수정, 비활성화가 권한에 맞게 동작한다. 가용 제외 수량 미만 총수량 축소와 활성 대여 비활성화는 409다. 수정 전·후와 비활성화가 감사 로그에 남는다. 단위 8/8, 통합 2/2, 세 컨테이너 healthy, 브라우저 오류 0건, `git diff --check` 통과.

## MP-11 — Phase 9 서비스 단위 테스트 확장

### ROLE
너는 도메인 규칙과 트랜잭션 경계를 검증하는 테스트 엔지니어다.

### GOAL
실제 DB 없이 비품 등록·수정·비활성화·대여·반납 서비스의 정상·실패 분기를 빠르고 결정적으로 검증한다.

### SCOPE
테스트 DB 클라이언트는 SQL과 파라미터를 기록하고 결과·오류를 제어한다. 등록 정규화와 중복 코드, 수정의 가용 제외 수량, 활성 대여 비활성화, 재고 초과 대여, 중복·분실 반납을 포함한다.

### CONSTRAINTS
구현 세부 호출 횟수보다 업무 결과와 트랜잭션 경계를 검증한다. 성공은 변경 SQL·감사 로그·COMMIT·release를 확인한다. 실패는 예상 DomainError 상태, 변경 SQL 미실행·ROLLBACK·release를 확인한다. 실제 PostgreSQL 무결성은 통합 테스트로 별도 검증한다.

### WORKFLOW
미검증 서비스 분기 식별 → 제어 가능한 DB 테스트 대역 작성 → 정상 경로 → 실패·경계 경로 → 단위 전체 실행 → Docker 통합 회귀 → 테스트 매트릭스·Phase 보고서 갱신 → GitHub 게시.

### SUCCESS
단위 17/17, 통합 2/2, 전체 19/19 통과. 실패·취소·skip 0건. 세 Docker 컨테이너 healthy. 비밀 패턴 0건과 `git diff --check` 통과.

## MP-12 — Phase 10 Docker 통합 시나리오

### ROLE
너는 프론트 프록시부터 PostgreSQL과 브라우저까지 왕복 흐름을 검증하는 통합 테스트 엔지니어다.

### GOAL
실제 Docker 3계층에서 인증·CSRF·RBAC·비품 CRUD·대여·반납·감사 로그가 하나의 업무 흐름으로 연결됨을 증명한다.

### SCOPE
Nginx `localhost:3000`을 단일 진입점으로 사용한다. 익명 401, CSRF 403, MANAGER·ADMIN 권한, 등록·상세·수정·비활성화, 대여·반납, 409 경계, 목록 제외와 감사 행위를 검사한다. 브라우저는 상세·감사 화면과 오류를 확인한다.

### CONSTRAINTS
테스트 데이터는 고유 코드를 사용한다. `finally`에서 감사 로그 → 대여 → 비품 순서로 정리한다. 기본 운영 데이터는 수정·삭제하지 않는다. 비밀번호·세션·CSRF 토큰은 출력하거나 저장하지 않는다. API 상태와 DB 결과를 함께 확인한다.

### WORKFLOW
3계층 health → 익명·세션 경계 → CSRF 실패 → MANAGER 업무 왕복 → 409 경계 → ADMIN 감사 확인 → 데이터 정리 → DB 서비스 통합 → 브라우저 상세·감사 회귀 → 전체 테스트 → 문서·GitHub 게시.

### SUCCESS
통합 3/3, 단위 17/17, 전체 20/20 통과. 실패·취소·skip 0건. 세 컨테이너 healthy. 브라우저 오류 0건. 테스트 잔존 데이터 없음. 비밀 패턴 0건과 `git diff --check` 통과.

## MP-13 — Phase 11 안전한 3계층 배포

### ROLE
너는 비밀값 보호, 재현 가능성, 빠른 롤백을 우선하는 릴리스 엔지니어다.

### GOAL
검증 commit을 Docker frontend·backend·PostgreSQL 3계층으로 배포하고 health와 핵심 보안 경계를 증명한다.

### CONSTRAINTS
비밀값을 Git·출력에 남기지 않는다. 예시값과 약한 비밀번호를 차단하고 운영에서는 HTTPS·secure cookie를 사용한다. frontend만 공개하며 검증되지 않은 DB 변경과 데이터 삭제를 금지한다.

### WORKFLOW
입력 확인 → 사전검사 → Compose 검사 → 백업 확인 → 빌드·기동 → health → 스모크 → 로그 → 성공 태그 또는 직전 태그 롤백 → 문서·commit·push.

### SUCCESS
세 서비스 healthy, health 200, 익명 401, 공식 반전 로고 200, 내부 서비스 비공개, 비밀 노출 0건, 롤백 절차 기록.
