# 장기 Goal+Harness 운영

이 Harness는 `docs/roadmap.md`의 P0~P7을 한 번에 한 Phase씩 실행하기 위한 기계 판독 계약이다. 자동 수행 범위는 로컬 읽기·비파괴 검증·현재 READY의 허용 파일 수정까지다. commit·push·원격 CI·배포·Secret·외부 메시지·실제 UAT는 승인을 대신하지 않는다.

## 명령

```powershell
npm.cmd run harness:status
npm.cmd run harness:check
npm.cmd run harness:verify
```

- `harness:status`: 현재 Phase와 READY를 JSON으로 출력한다.
- `harness:check`: 상태 파일의 단일 진행 Phase, 완료 수, READY·권한 불변식과 실제 Git branch provenance 일치를 검사한다. GitHub Actions에서는 `GITHUB_HEAD_REF`/`GITHUB_REF_NAME`, 로컬에서는 symbolic ref를 사용하며 해석 불가·불일치는 fail-closed한다.
- `harness:verify`: 현재 READY에 등록된 비파괴 로컬 검증만 실행한다. 현재 P6에서는 Git diff, 품질·계약, staging/Production 3서비스 health와 cutover Gate 실행기를 검사한다.

## P6/P7 가속 실행 큐

`P6_P7_ACCELERATION_QUEUE.json`은 외부 변경창을 기다리는 동안에도 실제 실행 자동화 공백을 한 건씩 닫는다. `READY` Packet은 정확히 하나이며 `WAIT_CHANGE_WINDOW`, `EXTERNAL_INPUT`, `NOT_RUN`은 실패로 세지 않는다.

- 실패 1회: 재현과 최소 수정
- 동일 실패 2회: 같은 수용조건의 대체 구현·도구·경로
- 동일 실패 3회: 자동 재시도 중단과 복구조건 기록
- P7 준비 산출물은 미리 만들 수 있지만 P6 완료 전 P7 상태를 활성화하지 않는다.
- P6 공개 전환은 `production:ingress-publication -- --execute`로 exact tunnel·runtime config·DNS를 게시한 뒤 `production:public-probe`를 실행한다. rollback token file reference와 publication·route-disable 확인 문자열이 없으면 게시하지 않는다.
- `production:cutover-preflight`의 Git·Docker·PowerShell·Cloudflare 명령은 각각 10초 상한과 1MiB 출력 상한을 사용한다. Cloudflare tunnel 조회가 timeout·실패·비정상 JSON이면 오류 원문 없이 `CLOUDFLARE_TUNNEL_OBSERVATION_FAILED` local blocker로 fail-closed하며 기존 tunnel 보존을 추정하지 않는다.
- `production:ingress-publication`은 Cloudflare CLI·PowerShell 관측에 10초·1MiB, Cloudflare API에 10초, DNS 관측에 5초 상한을 적용한다. 초기 DNS 관측이 끝나지 않으면 tunnel 생성·config·connector·DNS API 전에 `FAIL_INGRESS_PUBLICATION_CONTRACT`로 중단하고, provider 실패 메시지에는 token·응답·stdout/stderr 원문을 넣지 않는다.
- `production:route-disable`은 rollback 대상 tunnel CLI에 10초·1MiB, Cloudflare API에 10초, DNS 관측에 5초 상한을 적용한다. 초기 tunnel 관측 실패는 token read·DNS API 전에 중단하고, 삭제 뒤 provider·DNS 확인 실패는 변경 가능성을 보수적으로 기록한 `FAIL_ROUTE_DISABLE_PROVIDER_EXECUTION`으로 닫으며 token·응답·stdout/stderr 원문을 남기지 않는다.
- Production Cloudflare DNS rollback token의 존재 검사는 Secret content를 읽지 않는 공용 inspector를 사용한다. 실제 실행 경로만 저장소 밖 absolute physical file·1 byte~64KiB·fatal UTF-8·read 전후 repository/file identity·realpath·size 재검증을 수행하는 공용 bounded atomic Secret reader로 읽으며 ingress publication과 route-disable이 같은 계약을 공유한다.
- `production:public-probe`는 A·CNAME 관측을 5초로 제한하고 DNS 게시가 변경창 안에서 확인된 경우에만 exact HTTPS 5경로를 각각 10초 상한으로 동시에 호출한다. DNS timeout·실패는 HTTP 호출 0건으로 중단하고 endpoint timeout·응답 오류는 원문 없이 경로별 실패 결과로 정규화한다.
- `production:role-core-smoke`의 역할 로그인·MFA·RBAC HTTP 요청은 각각 10초로 제한한다. timeout·network·JSON 파싱 오류는 credential·provider 응답·오류 원문 없이 bounded 상태로 닫고, MFA 뒤 중간 실패 시 활성 시험 세션의 logout cleanup을 시도하되 cleanup 오류도 외부로 노출하지 않는다.
- `production:authenticated-idempotency`의 인증·쓰기 HTTP 요청과 Docker 조회·SQL은 각각 10초, process 출력은 1MiB로 제한한다. timeout·network·process·JSON 오류는 credential·provider·stdout/stderr 원문 없이 bounded 상태로 닫고, 중간 실패에도 marker 기반 DB cleanup과 활성 시험 세션 logout을 서로 독립적으로 모두 시도한다.
- `production:uat-actor-provision`의 Docker 관측·worker copy·cleanup은 10초, transaction worker는 60초, process 출력은 1MiB로 제한한다. timeout·process·worker JSON·cleanup 오류는 credential·stdout/stderr 원문 없이 닫고, 임시 worker 삭제 결과를 확인하기 전에는 provisioning 성공을 출력하지 않는다.
- `production:role-preflight`의 Production database container 조회와 role/MFA SQL 조회는 각각 10초·1MiB로 제한한다. timeout·process·container·SQL 결과 오류는 stdout/stderr 원문 없이 닫고, malformed·duplicate·unknown role 행은 준비 미완료로 조용히 축소하지 않고 검증 실패로 처리한다.
- `production:provider-preflight`의 backend container 조회는 10초, PostgreSQL storage·Defender bridge·AI health/readiness·loopback event publisher probe는 최대 150초, 모든 process 출력은 1MiB로 제한한다. timeout·process·container·observation JSON 오류는 stdout/stderr와 provider 오류 원문 없이 제한된 실패 코드로 닫는다.
- `production:csrf-idempotency-baseline`의 negative login HTTP·database container·두 SQL 조회는 각각 10초, process 출력은 1MiB로 제한한다. timeout·network·process·container·DB 결과 오류는 응답·stdout/stderr 원문 없이 닫고 session count와 5열 schema 결과는 정확한 비음수 정수만 허용한다.
- `production:ingress-publication`의 native A·CNAME 관측이 timeout·실패한 경우에만 Cloudflare 공개 DNS-over-HTTPS A·CNAME authoritative 응답을 대체 사용한다. 두 경로 실패, published/NXDOMAIN 충돌, 비정상 JSON과 HTTP 실패는 unpublished로 추정하지 않고 fail-closed한다.
- `production:log-gate`의 Docker container·backend log·outbox SQL 조회는 10초로 제한하고, process 출력은 일반 1MiB·로그 4MiB로 제한한다. timeout·process·container·malformed JSON·outbox 결과 오류는 stdout/stderr 원문 없이 닫으며 outbox 결과는 정확히 두 개 비음수 정수만 허용한다.
- `production:nonfunctional-baseline`의 child는 120초·1MiB로 제한하고 unrelated Secret 환경·raw stderr를 전달하지 않는다. child exit 0 외에도 exact target·60요청·오류율 0·p95 1000ms 이하·보안 헤더·익명 401·cross-site 403을 엄격 파싱하며 health·root·anonymous·cross-site HTTP는 각각 10초 상한이다.
- `production:operational-health-baseline`의 Docker container·SQL·backend log 조회는 10초, process 출력은 일반 1MiB·로그 4MiB로 제한한다. 단일 container·3개 비음수 counter·JSON object log를 엄격 파싱하고 backup은 symlink·경로 이탈을 차단한 physical file의 actual bytes와 streaming SHA-256으로 검증한다.
- `production:rollback-readiness`의 Docker `ps`·`inspect`·`volume ls`는 각각 10초·1MiB로 제한한다. 정확히 한 container ID와 그 ID로 시작하는 inspect identity, 40자리 revision·비어 있지 않은 image, 형식이 유효하고 중복 없는 volume 이름만 허용하며 timeout·process·JSON 오류 원문은 기록하지 않는다.
- `production:signoff-preflight`의 역할 결과 3건·업무/보안/운영 서명 3건 reference는 저장소 밖 절대경로의 서로 다른 physical JSON regular file만 준비 입력으로 인정한다. 상대경로·저장소 내부·symlink/reparse·디렉터리·빈 파일·1MiB 초과·동일 physical file 중복은 reference 누락으로 fail-closed하고 path·내용은 출력하지 않는다.
- `production:cutover-finalizer`와 `production:phase-promotion`은 동일 actual-evidence reader를 사용한다. 저장소 밖 절대경로의 real path가 일치하는 physical JSON regular file만 1 byte~4MiB로 읽고 actual bytes·SHA-256을 계산한다. actual bytes read 뒤 repository·candidate의 physical identity·realpath·size를 다시 검증하고 fatal UTF-8 JSON object만 허용해 저장소 내부·symlink/reparse·parent redirect·read 중 교체·invalid encoding·malformed JSON·배열을 원문 없이 fail-closed한다. 입력 부재는 기존처럼 WAIT다.
- `production:cutover-actual-evidence` 조립 입력은 파일당 1MiB, receipt 최대 64개·합계 16MiB로 제한한다. receipt root·repository·candidate의 physical identity·realpath·size를 actual bytes read 전후 재검증하고 fatal UTF-8 JSON object만 허용해 root redirect·read 중 교체·과대 입력·invalid encoding을 P6 actual 증거로 조립하지 않는다.
- 역할 시험은 `production:uat-actor-provision -- --execute`로 승인된 세 actor를 transaction provision한 뒤 `production:role-core-smoke -- --public`을 실행한다. 승인 파일과 세 credential reference는 저장소 밖 보호 파일만 허용한다.
- Production UAT 승인·ADMIN·MANAGER·USER credential JSON은 공용 64KiB bounded atomic reader를 거친다. 저장소 밖 absolute `.json` physical regular file·exact realpath·read 전후 repository/file identity·size·fatal UTF-8·JSON object를 강제하며 symlink/reparse·redirect·교체·과대·invalid encoding을 실행 입력으로 인정하지 않는다. 기본 dry-run과 P6 완료 전에는 Secret 원문을 읽거나 기록하지 않는다.
- P7 완료 증거는 `P7_OPERATIONS_HANDOVER_ACTUAL_EVIDENCE_CONTRACT.json`의 schema 2를 따른다. P6 cutover·운영 8영역·운영 서명 총 10개 실제 JSON은 각각 `{path, sha256}`로 참조하며 `operations:handover-finalizer`가 파일 존재·SHA-256·Production provenance·도메인 측정값을 검증한다. 계약 템플릿과 문자열-only 참조는 완료 증거가 아니다.
- P7 actual handover 최상위 manifest와 10개 하위 문서는 finalizer·assembler·8/8 completion이 공유하는 bounded reader를 거친다. 최상위는 저장소 밖 절대 `.json`, 하위 상대경로는 external manifest 디렉터리 내부만 허용하며 physical regular file·real path 일치·1 byte 이상·4MiB 이하·JSON object·actual bytes·SHA-256을 강제한다.
- P7 handover finalizer는 각 actual JSON의 bytes를 읽은 뒤 repository·external manifest base·candidate의 physical identity·realpath·size를 다시 확인하고 fatal UTF-8로 decode한다. read 중 동일 크기 교체·크기 변경·root/base redirect와 invalid encoding은 운영 완료 증거가 될 수 없다.
- P7 activation의 P6 actual evidence·unsigned approval request·OPERATIONS_OWNER MFA receipt·approval manifest와 재개 receipt는 approval request assembler·manifest assembler·read-only preflight·orchestrator가 공유하는 bounded reader를 거친다. 저장소 밖 절대 `.json`, physical regular file·real path 일치·1 byte 이상·4MiB 이하·JSON object·actual bytes·SHA-256을 강제하고 저장소 내부·symlink/reparse·parent redirect를 차단한다.
- 공용 external input reader는 actual bytes를 읽은 뒤 repository와 candidate의 physical identity·realpath·size를 다시 확인한다. JSON은 fatal UTF-8로 decode하므로 read 중 동일 크기 교체·크기 변경·root redirect와 invalid encoding이 approval·receipt·control·Secret provenance로 승격될 수 없다.
- P7 operations signoff input assembler의 P6 actual cutover·운영 8영역·OPERATIONS_OWNER approval receipt 10개 문서도 같은 bounded reader를 거친다. 조립 provenance에는 파싱 후 재직렬화가 아닌 실제 파일 bytes의 SHA-256을 사용하며 P6 완료 전에는 입력을 읽지 않는다.
- P7 SLO·alerting·backup/restore·certificate·onCall·maintenance·improvementQueue·operationsSignoff compiler의 actual 입력도 같은 bounded reader를 거친다. 각 compiler는 actual 파일 bytes의 SHA-256만 영역 evidence의 source provenance로 사용한다.
- P7 alert delivery·backup/restore·on-call drill·improvement queue runner의 provider manifest·approval attestation 4개 제어 JSON도 같은 bounded reader를 거친다. Credential 파일은 이 JSON 계약과 분리하며 P6 actual·P7 활성화·Production GO 전에는 어느 쪽도 읽지 않는다.
- P7 alert delivery·on-call drill·improvement queue runner의 credential 파일은 별도 64KiB bounded Secret reader를 거친다. 저장소 밖 physical regular file·real path·fatal UTF-8·비어 있지 않은 값을 강제하고 symlink/reparse·parent redirect·원문 오류 노출을 차단한다.
- P7 SLO JSONL ledger도 저장소 밖 physical UTF-8 전용 64KiB bounded reader를 거친다. P6 actual cutover 전에는 원장 content를 읽지 않고, 실제 append와 30일 export 재읽기 모두 같은 경계를 사용한다.
- 10개 실제 문서가 준비되면 `operations:handover-assembler -- --assemble`이 P6 완료·P7 진행 중 상태, 입력 10건, 저장소 밖 출력 경로와 정확한 확인 문자열을 검사한 뒤 finalizer를 선검증하고 schema 2 manifest를 원자적으로 1회 작성한다. 기존 출력은 덮어쓰지 않는다.

- `production:cutover-execute -- --resume-signoff --execute`는 Gate 12와 actual assembler/finalizer를 분리할 수 없는 한 흐름으로 실행한다. signoff resume 및 evidence assembly exact 확인, 저장소 밖 출력 경로를 Gate 12 전에 요구하고, 동일 run의 26 receipt·세 역할 결과·세 identity 서명 조립과 원자 기록까지 성공해야 `productionGo=true`다. 조립·검증·쓰기 실패는 exact public route-disable receipt를 요구한다.
- `production:phase-promotion`은 저장소 밖 actual P6 증거가 없으면 변경 0건으로 대기한다. `--promote`는 actual provenance·SHA-256·exact 확인·깨끗한 worktree를 검증한 뒤에만 P6 완료/P7 진행/7-of-8/Production GO, 가속 큐와 사람용 상태 marker 두 곳을 함께 갱신한다. P7 G0 Harness verifier는 전환 즉시 사용할 수 있다.
- `production:cutover-execute -- --execute --pause-before-signoff`는 Gate 1~11 뒤 저장소 밖 receipt root에 `<runId>.checkpoint`를 비덮어쓰기 방식으로 기록한다. 역할 결과·서명 참조 6건이 준비되면 `--execute --resume-signoff`가 checkpoint와 동일 run의 11 Gate·13 step receipt 및 SHA를 검증하고 Gate 12만 sequence 25부터 이어 쓴다. checkpoint는 최대 1MiB의 fatal UTF-8 JSON object로 읽고, receipt는 파일당 1MiB·최대 64개·합계 16MiB bounded atomic snapshot으로 읽는다. repository·receipt root·candidate identity·realpath·size를 read 전후 재검증하므로 같은 크기 교체·크기 변경·redirect는 재개 증거가 아니다. 변조·cutoff·Gate 12 실패는 exact route-disable adapter와 receipt 확인 없이는 격리 성공으로 처리하지 않는다. `production:cutover-signoff-resume-runtime-rehearsal`은 물리 임시 공간에서 같은 run 11+1 Gate·14 step·26 receipt·checkpoint 1건을 종단 검증하고 외부 변경은 수행하지 않는다.

## 상태 전이 규칙

1. 실제 완료 증거 없이 Phase 상태를 변경하지 않는다.
2. 완료 시 `MASTER_ROADMAP.json`, `docs/roadmap.md`, `docs/current-state.md`를 같은 Loop에서 맞춘다.
3. 다음 Phase 하나만 `in-progress`로 열고 READY를 정확히 하나 둔다.
4. 승인 게이트에서는 외부 명령을 실행하지 않고 정확한 대상과 행위를 보고한다.
5. 사용자 변경은 reset·clean·broad staging하지 않는다.
6. Phase 또는 가속 Packet 상태가 바뀔 때만 정본·체크리스트·증거를 동기화한다.
