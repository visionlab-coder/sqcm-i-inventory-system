# FR-009/016 기준정보 생명주기 메타프롬프트

ROLE:
서원토건 비품관리 시스템의 기준정보·PostgreSQL·관리자 UI 엔지니어다.

GOAL:
관리자가 자산 유형·모델·공급업체·위치를 조직 범위 안에서 생성·명칭 수정·활성/비활성화하고 기존 자산 참조와 이력을 보존한다.

USERS:
ADMIN은 기준정보를 관리하고 MANAGER/USER는 활성 기준정보만 업무 입력에서 사용한다.

CONTEXT:
Nginx SPA → Express Controller → Service → 신규 Repository → PostgreSQL 16 구조다. 현재 30개 테이블·migration 5개이며 기존 migration은 수정하지 않는다.

SCOPE:
4종 기준정보 조회·생성·명칭 수정·비활성화, 조직/부모/분류 참조 검사, 감사 로그, 관리자 UI, 컨셉 HTML, 테스트·문서·백업복구.

OUT OF SCOPE:
FR-013 파일 저장소, 자산 상태 전이 코드 추가, 물리 삭제, SSO/MFA, 운영 배포.

CONSTRAINTS:
ADMIN과 최근 재인증을 API·Service에서 검사한다. Controller에 SQL·업무 규칙을 넣지 않는다. 입력은 매개변수 SQL만 사용한다. 비활성화해도 FK와 기존 자산은 유지한다. 비밀번호·토큰·세션·제작 메타데이터를 저장하거나 표시하지 않는다.

TOOLS:
로컬 파일·Git, Node test, Docker Compose 3서비스, PostgreSQL, 브라우저 프리뷰, GitHub Issue/PR.

WORKFLOW:
Issue #7 → 006 migration → Repository → Service/단위 테스트 → Controller → 관리자 UI/컨셉 HTML → DB·HTTP·권한 테스트 → Docker/브라우저/로그 → 백업복구 → 문서 → commit/push/PR.

SUCCESS CRITERIA:
1. 4종을 같은 조직에서 생성하고 관리자 전체 목록에 표시한다.
2. 업무용 reference API는 활성 행만 반환한다.
3. 명칭 수정과 비활성화 후 기존 자산 FK·이력이 유지된다.
4. USER 403, 다른 조직/잘못된 부모·분류 4xx, 중복 409다.
5. 구문·단위·통합·브라우저·health·로그·복구·diff·Secret 검사가 통과한다.

FAILURE CRITERIA:
Controller SQL, 물리 삭제, 조직 범위 우회, 기존 migration 변경, FK 손실, 테스트 skip, 3서비스 unhealthy 중 하나라도 있으면 미완료다.

OUTPUTS:
006 migration, Repository/Service/Controller, 관리자 기준정보 UI, 컨셉 HTML, 단위·통합 테스트, 체크리스트·Phase 보고서.

VERIFICATION:
`npm run check`, Docker HTTP/DB 통합, health, 브라우저 스모크, 유지보수 점검, 백업·격리 복구, `git diff --check`, 비밀 패턴 검사.

MEMORY UPDATE:
요구사항 판정, migration 6, 테스트 수, 복구 증적, 남은 FR을 최신 문서에 기록한다.

STOP CONDITION:
모든 성공 기준과 CI를 통과하면 종료한다. 같은 원인의 실패가 3회 반복되면 증거와 필요한 결정을 보고하고 중단한다.
