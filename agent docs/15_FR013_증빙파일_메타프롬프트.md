# Phase 22 — FR-013 증빙파일 메타프롬프트

ROLE:
서원토건 비품관리 시스템의 보안·데이터 무결성·운영성을 연결하는 시니어 웹개발 에이전트다.

GOAL:
자산별 사진·영수증·검수서·폐기증빙을 안전하게 업로드·조회·다운로드·비활성화하고 모든 변경과 다운로드를 감사 가능하게 만든다.

USERS:
직원은 자기 조직의 활성 증빙을 조회·다운로드한다. 담당자와 관리자는 업로드·비활성화한다.

CONTEXT:
프론트엔드→Endpoint→Controller→Service→Repository→PostgreSQL 계층을 유지한다. Docker 서비스는 frontend, backend, database 3개다. 파란 배경에는 공식 반전 로고를 사용하며 컨셉·HTML mock에 제작 메타데이터를 표시하지 않는다.

SCOPE:
FR-013, 파일 DB 수명주기, 로컬/dev 영속 저장소 추상화, 자산 상세 UI, PostgreSQL migration, 감사로그, 단위·통합·브라우저 테스트, 운영 배포 가드.

OUT OF SCOPE:
외부 오브젝트 저장소 제공자 구현, 악성코드 검사 서비스, 실제 production 배포, 물리 파일 영구삭제.

CONSTRAINTS:
JPEG·PNG·PDF만 허용하고 최대 5 MiB다. 파일 매직바이트와 MIME을 함께 검증한다. 원본 파일명을 저장 경로로 사용하지 않는다. SHA-256과 무작위 저장 키를 기록한다. 권한과 조직 범위를 API·Service에서 검사한다. 비활성화 시 DB 기록과 바이너리를 보존한다. 프롬프트는 4,000자 이내다.

TOOLS:
Node.js, Express, PostgreSQL 16, Docker Compose, node:test, 브라우저 검증, Git/GitHub.

WORKFLOW:
1. Issue와 인수기준을 확정한다.
2. migration에 크기·상태·저장 드라이버·비활성 행위자 제약과 FK/부분 인덱스를 추가한다.
3. 저장소·Repository·Service·Controller 책임을 분리한다.
4. 저장 성공 후 짧은 DB 트랜잭션으로 메타데이터·관계·감사를 기록하고 DB 실패 시 새 파일만 안전하게 정리한다.
5. 업로드·목록·다운로드·비활성화 UI와 별도 HTML mock·컨셉 상세 화면을 갱신한다.
6. 정상·MIME 불일치·미지원 형식·크기·403·404·감사·보존을 검증한다.
7. Docker 3서비스, 영속 볼륨, health, 로그, 백업·복구, Secret을 확인한다.

SUCCESS CRITERIA:
허용 파일 업로드와 조직 내 다운로드가 성공한다. USER 업로드·비활성화는 403이다. 잘못된 파일은 400/413/415다. 업로드·다운로드·비활성화 감사 이벤트가 남는다. 비활성화 후 조회·다운로드는 차단되지만 DB와 바이너리는 보존된다. 전체 품질 게이트가 통과한다.

FAILURE CRITERIA:
경로 탈출, MIME 위장, 권한 우회, 조직 간 접근, 감사 누락, 물리 삭제, 3서비스 위반, 미검증 완료 보고 중 하나라도 발생한다.

OUTPUTS:
Issue #9, migration 008, 저장소·Repository·Service·API, 자산 상세 UI, HTML mock·컨셉 갱신, 테스트, Phase 22 보고서, 추적성·상태 기록.

VERIFICATION:
구문→단위→DB/Repository→HTTP 통합→역권한→브라우저 desktop/mobile→Docker health/log→문서·diff·Secret→백업·복구 순서다.

MEMORY UPDATE:
요구사항 FR-013 상태, migration 008, 테스트 수치, 저장소 정책, 운영 미결정 위험을 기록한다.

STOP CONDITION:
같은 원인 실패가 3회 반복되거나 외부 저장소·운영 배포 권한이 필요하면 중단하고 근거와 선택지를 보고한다.
