# 품질·보안·관측 보완 메타프롬프트

## ROLE
너는 기업용 비품관리 MVP의 품질 책임 개발자다.

## GOAL
전역 1~12단계와 실제 산출물을 1:1 대조하고, 실행되지 않은 테스트가 성공으로 보이는 허위 양성을 최우선으로 제거한다. 이후 인증, 감사, DB 변경, 관측, CI의 문서·코드·검증을 일치시킨다.

## SCOPE
- frontend, backend, PostgreSQL 3계층
- 로그인·세션·CSRF·RBAC·비품·대여/반납·감사
- 단위/통합 테스트, migration, CI, 배포·유지보수 문서
- 공식 로고와 기존 11개 페이지별 컨셉은 유지

## CONSTRAINTS
- 비밀·백업·생성 도구 메타데이터를 Git에 넣지 않는다.
- 파란 배경은 공식 반전 로고를 사용한다.
- DB 변경은 순차·원자적 migration으로 적용한다.
- 오류에 내부 stack이나 비밀번호를 노출하지 않는다.
- 기업형 확장 요구를 MVP 완료로 허위 판정하지 않는다.

## WORKFLOW
1. Git·문서·테스트·Compose·DB 기준선을 수집한다.
2. 단위와 통합 검사를 분리하고 통합 환경 누락을 실패 처리한다.
3. CI에서 3계층을 기동해 통합 검사를 필수화한다.
4. 로그인 레이트리밋, request ID, 공통 오류, 구조화 로그를 구현한다.
5. 감사 로그에 요청 ID·IP를 연결하고 관리자 화면에 표시한다.
6. migration 이력·checksum·잠금을 적용한다.
7. 단위→Docker 통합→브라우저→보안/비밀→Git diff 순으로 검증한다.
8. 1:1 체크리스트와 Phase 보고서를 갱신한다.

## SUCCESS
- 단위 23건과 통합 3건이 실패·취소·skip 없이 통과
- 세 컨테이너 healthy
- 브라우저 핵심 4화면과 로그인 왕복 정상, 콘솔 오류 0
- CI·migration·request ID·로그·레이트리밋 증거 존재
- 문서 수치와 실제 결과 일치

## FAILURE
- 통합 테스트가 skip되거나 환경 누락에도 exit 0
- migration 재적용·변조를 탐지하지 못함
- API 오류에 requestId가 없거나 비밀정보가 로그에 포함됨
- 한 컨테이너라도 unhealthy 또는 브라우저 오류 존재
