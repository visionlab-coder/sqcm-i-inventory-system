# FR-026/027 부분 입고·검수 메타프롬프트

## 역할
당신은 서원토건 비품관리 시스템의 백엔드·PostgreSQL·QA 담당자다.

## 목표
승인된 구매요청을 발주와 부분 입고로 처리하고, 검수 PASS 시에만 입고 수량만큼 추적 가능한 개별 자산을 생성한다. 검수 전에는 자산이 존재하지 않아 배정할 수 없도록 한다.

## 범위
- 승인된 PURCHASE 요청의 단일 발주
- 요청수량 이내 부분 입고와 발주 상태 계산
- PASS/FAIL/CONDITIONAL 검수
- PASS 검수·자산·상태이력·감사·outbox의 원자적 저장
- 검수와 자산의 다대일 추적 테이블
- 요청함 화면설계와 API/DB 테스트

## 제약
- PostgreSQL 16, 기존 3계층 Docker 구조를 유지한다.
- 라우터는 HTTP 변환만 담당하고 도메인 규칙은 서비스에 둔다.
- 조직 경계와 `request.review` 권한을 모든 쓰기에 적용한다.
- 동일 구매요청 중복 발주, 동일 입고 중복 검수, 동일 자산 중복 연결을 DB 제약으로 차단한다.
- 트랜잭션 안에서 외부 호출을 하지 않고 잠금 순서는 요청/발주 → 입고로 일관되게 유지한다.
- 컨셉아트와 HTML에는 도구·모델·프롬프트·내부 기능번호를 노출하지 않는다.

## 실행 절차와 판정
1. Issue를 만들고 완료 조건을 기록한다. 실패: Issue 없이 구현 시작.
2. 스키마를 멱등 마이그레이션으로 추가하고 FK 인덱스를 확인한다. 성공: 29개 필수 테이블과 유일 제약 확인.
3. 발주·입고·검수를 서비스 트랜잭션으로 구현한다. 성공: 누적수량 초과와 중복 검수는 409.
4. PASS 전 자산 0건, PASS 후 입고수량과 자산수 동일, FAIL 후 자산 0건을 검증한다.
5. 단위·통합·Docker health·유지보수·백업복구를 실행한다. 실패 시 원인과 잔여 위험을 보고한다.
6. 설계·DB·화면·테스트·Phase 보고서를 갱신하고 사용자 파일을 제외해 커밋·푸시한다.

## 종료 기준
자동 검증이 모두 통과하고 추적 문서가 실제 증적과 일치하면 완료한다. 브라우저 도구 자체 장애는 애플리케이션 결함과 분리해 잔여 인수 항목으로 기록한다.
