# FR-033/035 보고·감사 메타프롬프트

## 역할
서원토건 비품관리 시스템의 보고·감사·PostgreSQL 엔지니어로 작업한다.

## 목표
관리자가 조직 범위 안에서 부서·위치·유형·상태·취득기간별 자산을 집계하고 같은 조건으로 CSV를 내려받게 한다. 감사 담당자는 행위·대상·작업자·기간·변경 전후 값과 요청 ID를 검색한다.

## 범위
- 다차원 자산 보고 JSON API와 실제 SPA
- 동일 필터 CSV와 다운로드 감사 메타데이터
- 감사 로그 필터·변경값 자유검색 UI
- 입력 정규화 단위 테스트와 HTTP·PostgreSQL 통합 테스트
- 기존 보고서·관리 화면 컨셉 HTML 보완

## 제약
- USER는 보고·감사에 접근하지 못한다.
- 보고서는 MANAGER/ADMIN의 `report.read`, 감사는 ADMIN 권한을 서버에서 검사한다.
- 모든 필터는 SQL 전에 형식·범위·기간 순서를 검증하고 매개변수 SQL만 사용한다.
- 보고 화면과 CSV는 하나의 공통 필터 빌더를 사용한다.
- 반환은 최대 감사 200건으로 제한하고 비밀번호·세션·토큰을 검색·표시하지 않는다.
- 새 화면을 만들지 않고 기존 보고서·감사 페이지를 확장하며 제작 메타데이터를 표시하지 않는다.

## 실행·성공 기준
1. Issue와 완료 조건을 만든다.
2. 보고·감사 필터 서비스를 구현한다. 성공: 정상 정규화, 잘못된 ID·상태·날짜·역전 기간 400.
3. 부서·위치·유형·상태 집계와 총 취득가를 반환한다. 성공: 필터 대상만 집계.
4. 같은 필터 CSV를 만들고 `REPORT_EXPORTED` 감사 로그에 행 수와 필터를 남긴다.
5. 실제 SPA 필터 폼과 차원별 표, 감사 검색 폼을 연결한다.
6. USER 403, 관리자 보고·CSV·감사 검색, 테스트 데이터 정리를 자동 검증한다.
7. 문서·보고서를 실제 증적에 맞추고 사용자 파일을 제외해 커밋·푸시한다.

## 종료·실패 기준
단위·통합·Docker health·정적 UI·diff 검사가 모두 통과하면 완료한다. 브라우저 런타임 자체 오류는 앱 결함과 분리해 Issue #3에 유지한다.
