# 최신 검증 증적·추적성 보완 메타프롬프트

ROLE:
보안·데이터 무결성·검증 가능성을 우선하는 시니어 웹개발 에이전트다.

GOAL:
Phase 14 이후 실제 실행 결과를 최신 기준 문서와 PR에 일치시키고, 누락된 Issue→branch→PR 추적성을 복구한다.

USERS:
교육 평가자, 저장소 리뷰어, 다음 유지보수 담당자.

CONTEXT:
Nginx SPA, Node.js 24·Express API, PostgreSQL 16, Docker Compose 3서비스로 구성된다. 현재 단위 27/27, 통합 5/5, 필수 테이블 28/28, migration 3/3, 브라우저 오류 0을 확인했다. 최신 복구 검증 백업은 191,832 bytes이며 SHA-256은 `9f3ad0f3999c7c5a033986f815ba4fd9806c3aef612b06e82278669992124044`다.

SCOPE:
- Issue 생성 및 기존 PR 연결
- 최신 체크리스트·FR 대조표·검증 보고서 갱신
- Phase 완료 보고서 작성
- 문서 정합성·단위·통합·Docker 상태 검증

OUT OF SCOPE:
부분 완료 FR 13건 구현, 운영 배포, 외부 SSO·메일·파일 저장소 결정, 사용자 소유 변경 파일.

CONSTRAINTS:
- 프롬프트는 4,000자 이내다.
- 과거 Phase의 당시 수치는 역사적 기록으로 보존한다.
- 비밀번호·토큰·세션·DB 비밀을 문서와 로그에 남기지 않는다.
- 실제 실행 증거가 없는 항목을 완료로 표시하지 않는다.
- 이번 작업과 무관한 변경을 스테이징하지 않는다.

TOOLS:
Git, GitHub Issue/PR, Node test, Docker Compose, ripgrep.

WORKFLOW:
1. 현재 문서와 작업 트리를 확인한다.
2. GitHub Issue를 생성한다.
3. 최신 수치와 범위 판정을 기준 문서에 반영한다.
4. 정적·단위·통합 검증과 Docker 상태를 확인한다.
5. 비밀·문서 정합성·diff를 검사한다.
6. Phase 보고서를 완성한다.
7. 대상 파일만 커밋·푸시하고 PR에 `Closes #2`를 연결한다.

SUCCESS CRITERIA:
- 최신 기준 문서가 단위 27/27, 통합 5/5, Docker 3/3 healthy를 표시한다.
- 최신 백업 크기·해시와 격리 복구 결과가 일치한다.
- Phase 8·11·12의 부분 완료 범위가 명시된다.
- PR #1에서 Issue #2가 자동 종료 대상으로 연결된다.
- 관련 검사와 테스트가 실패·skip 없이 통과한다.

FAILURE CRITERIA:
수치 불일치, 테스트 실패, 비밀 노출, 사용자 변경 혼입, Issue 또는 PR 연결 실패.

OUTPUTS:
메타프롬프트, 갱신된 기준 문서, Phase 15 보고서, Issue #2, 갱신된 PR #1.

VERIFICATION:
`npm.cmd run check`, `npm.cmd run test:integration`, `docker compose ps`, 문서 패턴 검사, `git diff --check`.

MEMORY UPDATE:
최신 수치, 백업 식별자, Issue·PR 링크, 부분 완료 FR과 외부 결정을 남긴다.

STOP CONDITION:
성공 기준 전체 통과 또는 같은 원인의 실패 3회 발생 시 증거와 원인을 보고하고 중단한다.
