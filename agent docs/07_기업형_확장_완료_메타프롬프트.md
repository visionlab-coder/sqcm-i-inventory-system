# 기업형 비품관리 확장 완료 메타프롬프트

## ROLE
너는 서원토건 비품관리 시스템의 제품 책임자·보안 설계자·풀스택 개발자·QA·운영자다.

## GOAL
현재 교육용 MVP를 기업형 운영 기준으로 확장한다. 직원은 자산·요청·신고를, 담당자는 배정·이동·실사·수리를, 구매/재무/감사/관리자는 승인·구매·폐기·보고·조직·권한을 처리한다. 변경 전후와 요청 ID가 100% 추적돼야 한다.

## SCOPE
1. 조직·부서·위치·사용자·역할·범위 권한
2. 개별 자산번호·분류·모델·공급업체·확장속성·첨부 메타·전체 이력
3. 배정·반납·이동·수리·분실·구매 요청과 제출/승인/반려/완료
4. 발주·입고·검수, 수리, 폐기, 실사·불일치
5. 대시보드·검색·기간/상태 필터·보고서·권한형 CSV 감사
6. 비밀번호 재설정 토큰 구조·MFA/SSO 확장 필드·관리자 재인증 경계
7. 기존 11개 컨셉과 대응하는 실제 SPA 페이지
8. PostgreSQL migration, CI, 단위·통합·브라우저·백업복구
9. Draft PR 갱신·검사·병합 및 공유 대상 확인

## CONSTRAINTS
- frontend/backend/database 3컨테이너를 유지한다.
- 비밀·개인정보·백업·제작 메타데이터를 Git에 넣지 않는다.
- 파란 배경은 공식 반전 로고, 밝은 배경은 공식 컬러 로고를 쓴다.
- 변경 API는 CSRF·인증·기능 권한·조직 범위를 서버에서 재검사한다.
- 상태 변경은 목적별 command와 허용 전이표를 사용한다.
- 핵심 업무 변경·감사·outbox는 한 transaction으로 처리한다.
- 목록은 페이지네이션하고 오류는 code/message/fieldErrors/requestId 형식이다.
- 프롬프트 및 화면에 생성 도구·모델 메타데이터를 표시하지 않는다.
- 외부 공유 계정이 불명확하면 추측해 초대하지 않는다.

## WORKFLOW
1. 요구사항 FR-001~035를 DB/API/화면/테스트 수용기준으로 매핑한다.
2. 003 migration으로 기업형 테이블·제약·인덱스·기본 권한을 추가한다.
3. permission+organization scope와 상태전이 서비스를 단위 테스트로 먼저 만든다.
4. 조직/자산/요청/구매/수리/폐기/실사/보고 command API를 구현한다.
5. 11개 실제 화면과 역할별 메뉴·오류·빈 상태·모바일 흐름을 구현한다.
6. 정상·권한우회·조직침범·중복·잘못된 전이·재시도·세션/레이트리밋을 검증한다.
7. Docker 3계층 E2E, 브라우저 콘솔, 구조화 로그, 백업·격리복구를 검증한다.
8. 전역 1~12 문서·체크리스트·Phase 보고서·프롬프트 아카이브를 갱신한다.
9. 커밋·푸시·PR 검사 후 병합하고 main 상태를 재검증한다.

## SUCCESS
- FR-001~035 각각 구현 또는 검증 가능한 수용기준과 증거가 있다.
- 단위·통합·브라우저 검사 실패·skip 0, 세 컨테이너 healthy다.
- 조직침범·권한우회·잘못된 상태전이·중복 배정이 차단된다.
- 11개 실제 페이지, 공식 로고, 접근성 핵심 경계가 정상이다.
- migration·백업복구·감사·outbox·CSV 다운로드 이력이 확인된다.
- 문서와 실제 테스트 수치가 일치하고 원격 main 또는 명시적 외부 blocker만 남는다.

## FAILURE
- 기능을 컨셉아트/문서만으로 완료 처리함
- 테스트 skip, 범위 없는 RBAC, 무제한 PATCH, 감사 누락
- 비밀 노출, migration 변조, 한 컨테이너라도 unhealthy
- 불명확한 GitHub 계정을 임의 초대하거나 실패를 완료로 보고함
